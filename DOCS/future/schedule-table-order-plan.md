# Идея (future): чтение фактического порядка строк таблицы спецификации

## Статус

Отложено (решение 2026-09-11): модуль «Проставить позиции» работает на
исправленной самосортировке (числа по значению + натуральное сравнение текста).
Эта идея — запасной путь «на всякий случай», если где-то самосортировка снова
разойдётся с порядком Revit.

## Замысел

Нумеровать позиции строго по порядку строк, как их показывает Revit, читая
тело таблицы спецификации через API и привязывая строки к группам элементов:

1. `schedule.GetTableData().GetSectionData(SectionType.Body)` — тело таблицы.
2. Колонки — видимые поля в порядке `GetFieldOrder()` (скрытые поля колонок
   не имеют; колонку поля ADSK_Позиция исключать).
3. Тексты ячеек — `schedule.GetCellText(SectionType.Body, row, column)`
   (`TableView.GetCellText`, доступен с 2021).
4. Строка данных: ячейки имеют «параметрный» тип
   (`TableSectionData.GetCellType` — `Parameter`/`ParameterText`/
   `CombinedParameter`/`CalculatedValue`); заголовки групп и итоги — `Text`.
5. Привязка строки к группе — по «наиболее характерному» значению группы
   (обычно наименование): оно должно войти в текст строки (нормализация
   пробелов, ignore case). Защиты: 0 или ≥2 кандидатов на строку → строка
   неразобранная; сопоставились не все группы → честный fallback на
   самосортировку с предупреждением в логе.

## Что было выяснено опытным путём (важно для будущей реализации)

- В исследованных спецификациях поля группировки «Код по спецификации»
  (ElementType) и «ADSK_Наименование» СКРЫТЫ — колонок в таблице не имеют;
  видимое имя — объединённый параметр «ADSK_Наименование, ADSK_Конструктивная
  характеристика».
- У ячеек тела обычной спецификации `GetCellParamId` не заполнен — колонки по
  нему не ищутся; надёжно: порядок видимых полей `GetFieldOrder()` + `IsHidden`.
- Составляющие объединённого параметра: `ScheduleField.GetCombinedParameters()`
  → `TableCellCombinedParameterData` (`ParamId`); значения — через
  `FindParameterById` (элемент → элемент типа); точный рендеринг Revit
  (префиксы/суффиксы/разделители) не повторять — сравнивать «вхождением».
- Равенство по всем видимым параметрам слишком хрупко (форматирование чисел,
  пустые значения) — надёжнее вхождение наименования.
- Полезные дампы для отладки: перечень полей (имя/тип/скрыт) и все строки тела
  таблицы с текстами колонок.

## Контекст неудачных попыток (2026-09-11, версии v2–v6)

- Поиск колонок по `GetCellParamId` не работает в теле обычной спецификации.
- «Адрес» строки по одному «ADSK_Примечание» неуникален → коллизии.
- Режим строгого равенства по видимым параметрам даёт 0 кандидатов (числа с
  форматированием, пустые значения).
- Вывод: привязывать строку к группе только по наименованию (самое длинное
  непустое значение полей группировки) — иначе хрупко.
