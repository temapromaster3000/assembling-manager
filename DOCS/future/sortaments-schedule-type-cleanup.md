# Сортаменты: очистка копий PipeScheduleType

Статус: **future**, не начато. Найдено 25.11.2026 при проверке MCP-управления сортаментами.

## Проблема

При изменении размеров сегмента `SortamentService` копирует `PipeSegment` через
`ElementTransformUtils.CopyElements`. Вместе с сегментом Revit копирует и связанный
`PipeScheduleType` — в окне он называется «Спецификация/Тип».

Код видит, что `ScheduleTypeId` после копирования изменился, и продолжает работать
с новой спецификацией, но:

- старый `PipeScheduleType` не удаляется;
- новая копия не переименовывается обратно.

В результате при каждом изменении в модели появляются неиспользуемые типы
«Электросварная 1», «Электросварная 2», «Электросварная 3» и т.д.
Сам `PipeSegment` при этом переименовывается корректно — в списке сегментов
лишних записей нет.

Пример из лога 25.11.2026:

```text
copy created newSegmentId=570360 scheduleId=570359
copy changed scheduleId; using copied schedule
replacement final newSegmentId=570360 name='Сталь углеродистая - Электросварная'
delete segment completed id=18401 deletedCount=1
```

`deletedCount=1` — удалён только сегмент, спецификация осталась.

## Ожидаемое поведение

- После замены сегмента в модели остаётся один `PipeScheduleType` с исходным именем.
- Если старый тип используется другими сегментами — не удалять его, а записать предупреждение.
- Ошибки очистки не должны откатывать уже выполненную замену сегмента.

## План правки

1. В `ApplyReplacement` после `DeleteSegment` вызвать новый метод
   `NormalizeScheduleType(doc, originalScheduleId, newSegment, result)`.
2. Проверить, используется ли `originalScheduleId` другими `PipeSegment`
   (кроме уже удалённого).
3. Если не используется:
   - удалить старый `PipeScheduleType`;
   - новому `PipeScheduleType` вернуть исходное имя;
   - при ошибке удаления/переименования добавить предупреждение в `SortamentResult`.
4. Если используется другими сегментами:
   - ничего не удалять;
   - добавить предупреждение с именем типа.
5. Логировать старый id, новый id, имя и результат.
6. Отдельным этапом — разовая очистка уже накопившихся неиспользуемых
   `PipeScheduleType` в моделях пользователей (опционально, по согласованию).

## Затрагиваемые файлы

- `src/AssemblingManager.Revit/Services/SortamentService.cs`
- при необходимости — отчёт `SortamentResult` и окно «Сортаменты».

## Проверка

- [ ] update свободного размера: имя спецификации исходное, лишних типов нет.
- [ ] update используемого размера: трубы перенесены, спецификация одна.
- [ ] два изменения подряд: нет «Электросварная 1», «2».
- [ ] тип, общий для двух сегментов: не удаляется, есть предупреждение.
- [ ] Ctrl+Z после изменения: модель и спецификации возвращаются корректно.
- [ ] окно «Сортаменты» и MCP-запись работают как раньше.
