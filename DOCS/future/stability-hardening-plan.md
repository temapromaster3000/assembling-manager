# План: усиление надёжности Assembling Manager

## Статус

Отложено. План создан после статического аудита репозитория 2026-09-24.

## Цель

Сделать операции плагина предсказуемыми и безопасными для больших моделей, worksharing и обновлений. Приоритет — не добавлять новые возможности, а устранить ситуации, при которых модель может быть изменена частично, пользователю показывается ложный успех, а обновление может загрузить или установить непроверенные файлы.

## Результаты аудита, которые нужно закрыть

### P0 — безопасность и целостность данных

1. **Строгая проверка группирующего параметра**
   - Проверять не только существование, `InstanceBinding` и категории, но и текстовый тип параметра.
   - Проверять существующий параметр по имени, типу, GUID/определению и привязке, а не только по имени.
   - Проверять результат `Parameter.Set`; при `false` добавлять предупреждение или откатывать операцию.
   - Восстанавливать исходный `Application.SharedParametersFilename` даже если до операции он был пустым.
   - Затрагиваемые места: `src/AssemblingManager.Revit/Services/ParameterService.cs:16-84`, `152-237`, `347-363`, `468-536`; `src/AssemblingManager.Revit/Views/MainWindow.xaml.cs:240-285`.

2. **Корректная работа со спецификациями**
   - Искать конфликт только среди `ViewSchedule`.
   - Удалять при замене только `ViewSchedule`, не все `View` с совпадающим именем.
   - Проверять результат `ViewSchedule.Duplicate` и наличие допустимого имени.
   - Закрыть сценарий, где одноимённые план, 3D-вид и спецификация присутствуют одновременно.
   - Затрагиваемые места: `src/AssemblingManager.Revit/Services/ScheduleService.cs:85-153`; `src/AssemblingManager.Revit/Services/OrchestratorService.cs:498-565`; `src/AssemblingManager.Revit/Services/ViewService.cs:36-56`.

3. **Незаметная частичная ошибка модели**
   - Не проглатывать исключения при изменении вида, фильтра, типа вида, шаблона и параметра.
   - Разделить предупреждения, которые допустимы, и ошибки, которые должны приводить к rollback.
   - Добавить `Warnings` и список затронутых объектов в `ViewCreationResult`.
   - Показывать пользователю результат с предупреждениями, а не только счётчики.
   - Не увеличивать счётчики успешных операций, если API вернул `false` или объект не изменился.
   - Затрагиваемые места: `src/AssemblingManager.Revit/Services/FilterService.cs:129-195`; `ViewService.cs:579-652`; `OrchestratorService.cs:269-289`; `TagService.cs:696-800`; `PipeAxisService.cs:332-355`, `527-579`; `src/AssemblingManager.Core/Models/ViewCreationResult.cs`.

4. **Корректная обработка Revit failures**
   - В `FailurePreprocessor` обрабатывать только предупреждения.
   - Ошибки Revit не пытаться удалять как предупреждения.
   - Записывать severity, описание и элементы в отчёт.
   - При критической ошибке принудительно приводить транзакцию к откату.
   - Затрагиваемое место: `src/AssemblingManager.Revit/Services/FailurePreprocessor.cs:10-36`.

5. **Безопасное автоматическое обновление**
   - Проверять SHA-256 или цифровую подпись архива и DLL перед копированием.
   - Разрешать загрузку только с доверенного GitHub-релиза и ограничивать допустимые URL/имена файлов.
   - Проверять, что `StagingDir` и `TargetDir` находятся внутри разрешённого каталога.
   - Не удалять marker при частичном копировании.
   - При таймауте ожидания Revit не продолжать обновление.
   - Создавать резервную копию и применять набор файлов атомарно либо с возможностью отката.
   - Проверять результат копирования и завершать процесс с ненулевым кодом при ошибке.
   - Затрагиваемые места: `src/AssemblingManager.Revit/Updates/UpdateService.cs:101-168`, `408-454`; `src/AssemblingManager.Updater/Program.cs:67-107`, `110-219`.

### P1 — корректность в сложных моделях

   - Не менять виды, выбранные пользователем для сохранения, если операция затронула общий фильтр.

## Предлагаемый порядок реализации

1. P0: валидация параметров, типизированные спецификации, ошибки/rollback и безопасный updater.
2. P1: метаданные `AssemblyInstance.Id`, worksharing, проверки открытых видов и повторная обработка.
3. P2: индексация модели, UX, схемы настроек, тестируемая логика.
4. Отдельно: сборка, CI, релизные скрипты, документация и ручная проверка пяти версий Revit.

Изменения следует разбивать на небольшие законченные задачи: безопасность модели, безопасность обновления, идентификация объектов, worksharing, производительность, тестирование. Не объединять все исправления в один большой рефакторинг без промежуточной проверки.

## Критерии готовности

- Ошибка записи параметра, применения фильтра, замены вида или обновления не приводит к тихому `Succeeded`.
- Все действия с моделью либо завершаются с отчётом, либо полностью откатываются.
- Одноимённые виды разных типов никогда не удаляются вместо друг друга.
- Сборки с похожими именами не обрабатывают чужие виды.
- Плагин корректно работает с занятыми элементами и не меняет чужие настройки без явного решения.
- Непроверенный или частично скопированный updater никогда не сообщает об успешном обновлении.
- Все пять конфигураций R21–R25 собираются воспроизводимо.
- Для критических сценариев есть автоматические тесты или документированная ручная проверка.

## Чек-лист ручной проверки в Revit

Агент не может запустить Revit, поэтому проверку выполняет пользователь.

### Подготовка тестовой модели

- [ ] Создать сборки с именами `Узел A` и `Узел A_1`, чтобы проверить пересечение префиксов.
- [ ] Создать одноимённые план, 3D-вид и спецификацию с разными типами.
- [ ] Создать параметр `ADSK_Группирование` с типом Integer и проверить отказ плагина.
- [ ] Создать view template, который блокирует фильтры.
- [ ] Создать пользовательские разрезы с именами по шаблону `<сборка>_...`.
- [ ] Подготовить workshared-модель с занятым элементом, доступным другому пользователю.
- [ ] Подготовить большую модель с большим количеством сборок, видов, марок и осей.

### Основные операции

- [ ] Запустить создание видов на модели без активного документа — получить понятный отказ без исключения.
- [ ] Создать новый комплект видов и проверить план, четыре разреза, 3D и спецификацию.
- [ ] Повторить запуск с действиями «Оставить», «Обновить», «Заменить» для каждого типа вида.
- [ ] Проверить, что «Оставить» не изменяет геометрию, параметры и фильтры.
- [ ] Проверить, что «Обновить» сохраняет пользовательское оформление и состав полей спецификации.
- [ ] Проверить, что при ошибке одного вида выполняется полный откат.
- [ ] Проверить параметры `A` и `A_1`: чужие разрезы не должны обрабатываться.
- [ ] Проверить одноимённые виды разных типов: замена спецификации не должна удалять план или 3D.
- [ ] Проверить блокирующий view template: пользователь должен получить предупреждение до изменения модели.
- [ ] Проверить, что отчёт показывает частичные ошибки и фактические счётчики.

### Worksharing и служебные операции

- [ ] Повторить операции с занятыми видами, фильтрами, марками и осями.
- [ ] Проверить, что чужие элементы пропускаются, а владельцы указаны в отчёте.
- [ ] Проверить пересоздание фильтра при изменении набора категорий.
- [ ] Проверить, что фильтр не применяется к видам, выбранным для сохранения.
- [ ] Проверить размещение видов на листах при большом количестве элементов и отсутствии свободного места.

### Обновление

- [ ] Проверить скачивание релиза и запуск updater после закрытия Revit.
- [ ] Проверить отказ при неверном SHA-256, неверном имени файла или недоверенном URL.
- [ ] Проверить, что при неудачном копировании marker сохраняется для повторной попытки.
- [ ] Проверить, что updater не продолжает работу, если Revit не завершился за отведённое время.
- [ ] Проверить обновление всех установленных версий R21–R25.
