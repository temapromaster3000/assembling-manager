# Автозапуск Telegram-бота Assembling Manager

Статус: **future**, не начато. Основа — рабочий ручной режим из
`docs/realized/telegram-integration-plan.md`.

## Цель

Запускать Telegram-бота автоматически при входе пользователя в Windows и держать
его в фоне без открытого чёрного окна, сохранив простую остановку и понятные логи.

## Требования

- запуск от текущего пользователя, без службы от `SYSTEM`;
- один экземпляр бота и один сервер песочницы;
- без входящих портов и webhook;
- токен — только в переменных окружения пользователя;
- песочница OpenCode, агент `revit` и MCP-мост — как в ручном режиме;
- логи в `%LOCALAPPDATA%\AssemblingManager\TelegramBot\logs`;
- если Revit закрыт, бот продолжает работать и отвечает `BRIDGE_NOT_FOUND`;
- остановка одной командой или ярлыком;
- автозапуск не должен затрагивать основной OpenCode.

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| Ярлык в `shell:startup` | Просто, без прав администратора | Окно скрыто, падение заметно только по логам; VBS-обёртку могут блокировать политики |
| Планировщик задач Windows | Надёжный запуск при входе, можно перезапускать, не нужен админ | Чуть сложнее настройка |
| Служба Windows (NSSM/WinSW) | Работает без входа пользователя | Сложно, токен и профиль пользователя, не рекомендуется для первой версии |
| Автозапуск только сервера | Меньше скрытых процессов | Бот всё равно запускается вручную — цель не достигнута |

**Рекомендация:** Планировщик задач Windows + отдельный скрытый скрипт запуска.
Ярлык «Остановить Telegram-бота» — на `stop-telegram-bot.bat`.

## Предлагаемая реализация

1. `tools/telegram-bot/start-telegram-bot-hidden.ps1`:
   - проверяет, не запущен ли уже бот (mutex или поиск процесса);
   - запускает сервер песочницы и бота без окна;
   - пишет объединённый лог запуска;
   - при завершении бота останавливает сервер;
   - создаёт/обновляет PID-файл.
2. `tools/telegram-bot/install-autostart.ps1`:
   - создаёт задачу Планировщика «AssemblingManager Telegram Bot»;
   - триггер — вход текущего пользователя;
   - действие — скрытый запуск `start-telegram-bot-hidden.ps1`;
   - условие «выполнять только при входе пользователя» (не от SYSTEM).
3. `tools/telegram-bot/remove-autostart.ps1`:
   - удаляет задачу Планировщика;
   - останавливает бота и сервер песочницы.
4. `tools/telegram-bot/README.md`:
   - раздел «Автозапуск»;
   - как проверить, что задача создана;
   - как посмотреть логи и остановить.
5. При необходимости — health-check: если бот упал, задача перезапускает его
   с задержкой, но не создаёт второй экземпляр.

## Что не делать в первой версии

- Не ставить службу Windows.
- Не запускать от `SYSTEM` и не открывать порты.
- Не хранить токен в файле задачи или репозитории.
- Не менять глобальный конфиг обычного OpenCode.
- Не добавлять автозапуск Revit — только бота.

## Ручная проверка

- [ ] Вход в Windows — бот стартует один раз, окно не появляется.
- [ ] В Telegram `/start` отвечает без ручного запуска.
- [ ] Второй экземпляр не создаётся (повторный вход/запуск).
- [ ] Логи пишутся в `%LOCALAPPDATA%\AssemblingManager\TelegramBot\logs`.
- [ ] Ярлык «Остановить Telegram-бота» останавливает бота и сервер.
- [ ] После остановки сообщения не обрабатываются, при следующем запуске
      старые апдейты выбрасываются.
- [ ] Revit закрыт — бот отвечает `BRIDGE_NOT_FOUND`, не падает.
- [ ] Основной OpenCode и его сессии не затрагиваются.
- [ ] Задача Планировщика не требует прав администратора при каждом запуске.

## Риски

- Скрытый процесс сложнее заметить; нужен понятный лог и health-check.
- Политики компании или антивирус могут запрещать автозапуск скриптов.
- При смене пользователя Windows токен и ID нужно настроить заново.
- После обновления бота или OpenCode автозапуск нужно проверить повторно.
- Если бот уже запущен вручную, планировщик не должен создавать второй экземпляр.

## Решение

Пока не реализовывать. Вернуться после стабилизации ручного режима и, при желании,
после первых реальных задач через Telegram.
