# Telegram-управление Revit через MCP

Статус: **future**, не начато. Основа — уже работающий MCP-мост Assembling Manager
и MCP-сервер `revit`. Текущий план MCP: `docs/in-progress/mcp-sortaments.md`.

## Цель

Управлять сортаментами труб из Telegram обычным текстом: запрос → предпросмотр →
подтверждение кнопкой → применение. Позже — другие модули плагина.

Требования:

- бот работает только на компьютере пользователя;
- никаких открытых входящих портов;
- доступ только для разрешённых Telegram ID;
- запись в модель — только после подтверждения;
- выключатель записи в Revit остаётся вторым независимым предохранителем.

## Архитектура

```text
Telegram
   │  long polling (исходящие соединения)
   ▼
Бот на этом ПК
   │  локальный opencode API / session
   ▼
opencode V2 service
   │
   ▼
MCP-сервер revit
   │  именованный канал + токен
   ▼
MCP-мост в Revit
   │  ExternalEvent → TransactionGroup
   ▼
Revit API
```

- Бот запускается на этом же компьютере, где открыт Revit.
- Long polling: бот сам обращается к Telegram, входящие порты не открываются.
- `opencode` слушает только `127.0.0.1`.
- Токен бота хранится в переменной окружения, не в git.
- MCP-мост и выключатель записи — как в текущей реализации.

## Этапы

### Этап 0. Разведка и выбор бота

- [ ] Проверить `@grinev/opencode-telegram-bot`: совместимость с opencode V2 service,
      поддержка сессий, inline-кнопок и подтверждений.
- [ ] Если готовый бот не подходит — минимальный собственный бот
      (`python-telegram-bot` или `aiogram`) с вызовом локального opencode API.
- [ ] Зафиксировать решение и схему запуска в этом плане.

### Этап 1. Запуск и доступ

- [ ] Создать бота в BotFather, токен — в переменную окружения.
- [ ] Whitelist Telegram user ID; все остальные сообщения игнорируются.
- [ ] Long polling, без webhook и без открытых портов.
- [ ] Логи без токена и без содержимого личных сообщений.
- [ ] Команда/кнопка отключения бота.

### Этап 2. Подключение к opencode и MCP

- [ ] Настроить opencode V2 service на `127.0.0.1`.
- [ ] Создать отдельную сессию/проект для Revit-задач.
- [ ] Передать агенту инструкции: сначала `status`, писать только через
      `preview_pipe_size_change` → `apply_pipe_size_change`.
- [ ] Проверить, что из бота доступны MCP-инструменты `revit`.

### Этап 3. Подтверждение через inline-кнопки

- [ ] Агент делает предпросмотр и возвращает план.
- [ ] Бот показывает план и кнопки **«Применить» / «Отмена»**.
- [ ] «Применить» → `apply_pipe_size_change` с сохранённым `previewId`.
- [ ] «Отмена» → удалить/просрочить предпросмотр, ничего не менять.
- [ ] Повторное нажатие кнопки не должно применять изменение дважды.
- [ ] По умолчанию в Telegram **не включать** автоматическое применение без кнопки.

### Этап 4. Ошибки и ограничения

- [ ] `WRITE_DISABLED` — понятное сообщение «запись выключена в Revit».
- [ ] `PREVIEW_EXPIRED` / `CATALOG_CHANGED` — предложить повторить запрос.
- [ ] `WORKSHARING_BUSY` — показать, кто занял элементы.
- [ ] `TIMEOUT` / Revit закрыт — сообщение без падения бота.
- [ ] Один сегмент за вызов; DN — ключ и не меняется.

### Этап 5. Проверка

- [ ] Бот отвечает только whitelisted ID.
- [ ] Предпросмотр приходит в Telegram с планом и кнопками.
- [ ] «Применить» применяет ровно показанный план.
- [ ] «Отмена» ничего не меняет.
- [ ] Повторный callback не применяет дважды.
- [ ] `WRITE_DISABLED` и закрытый Revit обрабатываются корректно.
- [ ] Ctrl+Z в Revit откатывает изменение одним шагом.

### Этап 6. Документация и упаковка

- [ ] Инструкция: токен, whitelist, запуск, остановка, логи.

## Безопасность

- Whitelist ID, режим «запрещено всё, кроме разрешённых».
- Токен только в переменной окружения.
- opencode API только на `127.0.0.1`.
- Подтверждение перед записью — обязательно.
- Выключатель записи в настройках плагина — второй предохранитель.
- В логах не хранить токен и личные сообщения.
- Возможность отключить бота одной командой.

## Открытые вопросы

- Готовый бот `@grinev/opencode-telegram-bot` или собственный?
- Нужен ли первый этап только для чтения (без записи)?
- Хранить ли историю диалога и на сколько?
- Как обрабатывать несколько одновременных запросов (очередь)?
- Нужен ли доступ вне домашней сети? Если да — только через VPN,
  без проброса портов.

## Ограничения

- Не запускать несколько ботов на один токен одновременно.
- Не открывать webhook и входящие порты.
- Не давать боту доступ к файлам и shell за пределами задачи.
