# Модуль «Проставить позиции» — этап 2: марки на видах

## Идея

Продолжение модуля «Проставить позиции». Этап 1 (запись позиций в спецификации
сборок) реализован. Этап 2 — после выбора ключевых слов и спецификаций пользователь
вторым окном выбирает типоразмеры марок для категорий элементов, а плагин после
записи позиций проставляет марки на планах и разрезах сборок.

Модуль реализуется в ТОЙ ЖЕ кнопке «Проставить позиции» — отдельная кнопка ленты
не создаётся.

## Поток

1. Окно 1 `AssignPositionsDialog` (существующее): ключевые слова + выбор спецификаций.
2. Кнопка «Выполнить» → команда собирает категории элементов выбранных спецификаций
   и типы марок в проекте → окно 2 `AssignTagsDialog` (новое):
   - список категорий элементов;
   - напротив каждой категории ComboBox с марочными семействами/типоразмерами
     («Семейство : Типоразмер»), подходящими для категории;
   - значение по умолчанию — «— Пропустить —» (категория не маркируется);
   - сводка «Выбрано марок: X из Y категорий», кнопки Отмена/Выполнить.
3. После «Выполнить» — одна транзакция: запись позиций (этап 1) + простановка марок.
4. Отчёт: позиции (как раньше) + марки (создано/удалено/ошибки).

## Поведение

### Определение сборок и видов
- Сборка для спецификации определяется по фильтру спецификации
  (`ScheduleFilterType.Equal` по полю группировки, значение = имя сборки);
  при отсутствии фильтра — имя сборки = имя спецификации без суффикса `_Спецификация`.
- Виды сборки: `ViewService.GetExistingAssemblyViews` (имена `{Сборка}`, `{Сборка}_Вид спереди`
  и т.д.), принимаются только `ViewPlan` и `ViewSection` (3D-виды не маркируются).
- Если вид не найден — предупреждение в отчёт, элемент не маркируется.

### Выбор марок в проекте
- Все загруженные `FamilySymbol`, у которых категория семейства — «марка»
  (имя `BuiltInCategory` оканчивается на `Tags`), кроме системных
  (ключевые заметки, марки материалов и т.п.), плюс мультикатегорийные марки
  (`OST_MultiCategoryTags` — доступны для любой категории).
  Категория читается у самого `FamilySymbol` (`symbol.Category`), т.к. у класса
  `Family.Category` часто не реализован и возвращает null (известный нюанс,
  The Building Coder); fallback — `Family.FamilyCategory`, затем `Family.Category`.
  Дополнительный источник — типы уже существующих в модели `IndependentTag`
  (их семейства добавляются в пул марок через `tag.GetTypeId()`).
- Соответствие «категория элемента → категория марки» — словарь пар
  `BuiltInCategory` (элемент → марки): архитектура (`OST_Doors → OST_DoorsTags`),
  МЕП (`OST_PipeCurves → OST_PipeTags`, `OST_PipeFitting → OST_PipeFittingTags`,
  воздуховоды, оборудование, электрика и т.д.), исключения колонн
  и моделей (`OST_GenericModel → OST_ModelTags`/`OST_GenericModelTags`).
  Если категория отсутствует в словаре — fallback «имя + Tags».
- Если для категории нет подходящих марок в проекте — ComboBox пустой
  (заглушка «Нет марок»), категория автоматически «пропускается».
- Окно 2 показывается ВСЕГДА (если в спецификациях есть элементы), даже когда
  подходящих марок не найдено; в этом случае выводится предупреждение,
  а позиции всё равно записываются.
- Диагностика в лог: категории элементов спек, все найденные категории марок
  с семействами, кандидаты и количество опций по каждой категории; при открытии
  окна 2 — число записей пресета и для каждой категории: нашлась ли запись и
  найден ли `Семейство|Типоразмер` (сопоставление по именам, Trim +
  OrdinalIgnoreCase).
- Окно 2 — поле «Мин. смещение марки от элемента (мм)»: по умолчанию 500,
  диапазон 200–3000; фиксированные модельные мм, от масштаба вида не зависят;
  значение сохраняется в пресет (поле `MinOffsetMm`) и восстанавливается при
  следующем запуске.
- Окно 2 — поле «Высота зоны марки (мм, эталон — масштаб 1:100)»: по умолчанию
  300, диапазон 50–2000 — реальная видимая высота марки (текст + полка);
  сохраняется в пресет (`ZoneHeightMm`).
- Окно 2 — выбор «Текст марки»: «Только над полкой» (по умолчанию) или
  «Над и под полкой»; сохраняется в пресет (`TextBelowShelf`).
- **Масштабирование**: высота зоны и запас — модельные мм с эталоном 1:100,
  при простановке в виде умножаются на `view.Scale / 100` (привязаны к видимой
  графике марки, которая масштабируется со scale); мин. смещение — фиксированные
  модельные мм, от масштаба вида не зависят (элементы модели не масштабируются).
  Замеры bbox (LeftGap/RightGap изломов) выполняются в самом виде и
  масштабируются автоматически.
- Пресет выбранных типоразмеров марок сохраняется при «Выполнить»
  (категория → «Семейство|Типоразмер») и предзаполняет ComboBox'ы; пресет
  не применяется, если семейство/типоразмер выгружен из проекта.

### Создание марок
- Марки создаются ТОЛЬКО для элементов с заполненным параметром `ADSK_Позиция`
  (строки, пронумерованные этапом 1). Элементы из строк, пропущенных по ключевым
  словам (позиция пустая), не маркируются — счётчик «пропущено элементов».
- Правила пропуска элемента (марка не ставится): нет позиции; элемент невидим в виде
  (`get_BoundingBox(view)` пуст); элемент «смотрит в нас» (вертикальные трубы на
  плане и т.п.: если у элемента есть коннекторы `FamilyInstance.MEPModel.ConnectorManager`
  / `MEPCurve.ConnectorManager` и **все** их оси `Connector.CoordinateSystem.BasisZ`
  параллельны направлению взгляда вида, `|dot| >= 0.95`); элемент является вложенным
  общим семейством, у которого **любой из предков** по цепочке
  `FamilyInstance.SuperComponent` «смотрит в нас» (коннекторы у таких вложенных
  часто сидят в родителе-арматуре, поэтому проверяется вся цепочка до корня) —
  счётчик «Пропущено (смотрит в нас)».
- Точка привязки марки (конец выноски) — центр bbox элемента в виде.
- Создание: `IndependentTag.Create(doc, view.Id, reference(элемент), addLeader: true,
  TagMode.TM_ADDBY_CATEGORY / TM_ADDBY_MULTICATEGORY, TagOrientation.Horizontal, anchor)`;
  выбранный типоразмер: `tag.ChangeTypeId(symbolId)` (доступно с Revit 2019).
- Выноска со свободным концом: через API марку нельзя сразу создать со свободным
  концом — она создаётся с присоединённой выноской, затем
  `LeaderEndCondition = Free` + `SetLeaderEnd(ref, anchor)` (R21: `LeaderEnd = anchor`)
  — кончик выноски в центре элемента.
- Позиция головы — диагональная лесенка «марка ↔ марка» (пересечения с
  элементами/семействами НЕ проверяются):
  - перебор по кругу на каждом кольце лесенки: право-вверх → влево-вверх →
    право-вниз → влево-вниз; первый свободный кандидат берётся сразу —
    верхнего приоритета нет, марки расходятся во все четыре стороны
    равномерно;
  - 9 колец (8 шагов): один шаг = одна высота зоны по вертикали (расстояние
    по диагонали = высота зоны / 0.7071) — соседние кандидаты не лежат
    друг в друге;
  - fallback — место по умолчанию (право-вверх, «Мин. смещение»), наложение
    допустимо, предупреждение в лог.
- Зона марки для проверки наложений — отсчитывается от уровня полки
  (`TagHeadPosition` = горизонтальная опорная плоскость семейства), а НЕ от
  центра bbox: замеренные Up/Down для зоны и лесенки больше не используются,
  поэтому невидимые вспомогательные линии семейств (раздувающие bbox) не
  влияют на зону:
  - «Текст только над полкой»: вверх = высота зоны (H), вниз = только запас;
  - «Текст над и под полкой»: вверх = H/2, вниз = H/2;
  - по горизонтали: LeftGap/RightGap как измерено (длинные линии полки реально
    видны и занимают место); при неудачном замере — тонкий прямоугольник
    (только запас);
  - запас — 3 модельных мм, масштабируется вместе с видом.
  Поиск места выполняется всегда (зона не зависит от замера); если замер не
  удался — только излом ставится в голову марки (fallback).
- Точка излома выноски — по стороне, обращённой к элементу:
  - голова справа от элемента (right-up/right-down):
    `голова - (LeftGap + 1 мм)` — левый край полки;
  - голова слева от элемента (left-up/left-down):
    `голова + (RightGap + 1 мм)` — правый край графики по пробному замеру,
    без ограничения. Безопасно: пробник мерит ДО записи позиций (по старому
    тексту), поэтому RightGap всегда в пределах 0.82–1.31 фута (250–400 мм =
    2,5–4 мм на листе 1:100) — источник метровых отводов (5.48 фута у
    финальной марки с длинным текстом) в коде больше не существует;
  - замер не удался (fallback): излом в голове марки.
  Разрывы полки (L/R/U/D) измеряются пробной маркой ДО основной транзакции
  (методика Таммича: TransactionGroup + пробная марка с выноской → Free →
  голова и излом в точку конца выноски → Commit → bbox → RollBack; кэш по
  типоразмер+вид — `PrepareTagDimensions` + `MeasureTagDimensions`). Излом
  ставится `SetLeaderElbow` (R22+) / `LeaderElbow` (R21), затем
  `TagHeadPosition = head`.
- ВАЖНО про семейства: `TagHeadPosition` = начало координат семейства. Если оно
  не совпадает с началом полки, излом придёт не в начало полки. По замерам
  `ADSK_Марка:Марка` — начало в левом краю полки (L = 0), а у `ADSK_Марка_5`
  начало утоплено на 0.82 фута (25 см) правее — для таких семейств излом
  смещается внутрь полки; лечится правкой семейства (выровнять графику так,
  чтобы левый конец полки был в начале координат).
- Предыдущий движок поиска места (20 лучей, зоны препятствий по геометрии,
  4 прохода поиска, гарантии «за рамкой») откачен: порождал бесконечные правки
  и непредсказуемое поведение. Вместо него — простое уклонение «марка ↔ марка»
  по прямоугольникам полок с чередованием диагоналей и запасными направлениями.

### Повторный запуск
- Каждая созданная марка помечается Entity (ExtensibleStorage-схема
  `AssemblingManagerPositionTag`, поле = имя сборки).
- Перед простановкой марки плагина с этой схемой удаляются только в тех видах,
  где будет выполняться простановка; ручные марки не затрагиваются.

### Пресет выбора марок
- `TagPresetStorage` (ExtensibleStorage, DataStorage, схема
  `AssemblingManagerPositionTagPreset`, GUID обновлён при добавлении полей —
  старые пресеты в моделях сбрасываются один раз): список строк
  «Категория|Семейство|Типоразмер» + `MinOffsetMm` + `ZoneHeightMm` +
  `TextBelowShelf`.
- При повторном открытии окна 2 ComboBox предзаполняются сохранёнными марками,
  если семейство/типоразмер ещё существует в проекте; высота зоны и положение
  текста восстанавливаются из пресета.

## Контрольный список ручной проверки

1. Открыть модель со спецификациями сборок (ADSK_Позиция), планами и разрезами сборок.
2. Запустить «Проставить позиции», выбрать спецификации, нажать «Выполнить».
3. Во втором окне: для категории с элементами в спеке есть марки в выпадающем
   списке; по умолчанию «— Пропустить —».
4. Выбрать марку для категории, нажать «Выполнить»: позиции записаны, на плане и
   разрезе сборки появились марки с выноской (свободный конец), кончик выноски в
   центре элемента, голова — по диагонали вправо-вверх на заданное смещение,
   точка излома — у края полки со стороны элемента (марка показывает номер
   позиции, если в семействе марки есть метка на ADSK_Позиция).
5. Категория «Пропустить» — элементы не маркированы.
6. Плотный узел: марки не налезают друг на друга и расходятся по кругу
   (право-вверх → влево-вверх → право-вниз → влево-вниз), поднимаясь на шаг
   после полного кольца; излом — у края полки со стороны элемента: правые
   марки — слева, левые — справа у текста (без длинных отводов).
7. Если все кандидаты заняты — марка на месте по умолчанию (право-вверх, мин.
   смещение), наложение допустимо; в логе предупреждение «no free tag head
   position».
8. В логе: offset кратен высоте зоны, direction right-up/left-up/right-down/
   left-down, scale 1:<масштаб вида>; для каждого типоразмера+вида — строка
   «Tag dims measured».
9. Невидимые вспомогательные линии семейств марок НЕ влияют на зону: зона
   откладывается от полки на заданную «высоту зоны» (проверить: зоны марок
   равны на глаз заданному размеру независимо от семейства).
10. Выбор «Только над полкой»: зона целиком вверх от полки, снизу только
    запас; «Над и под полкой»: зона пополам.
11. Масштаб: сменить масштаб вида узла (например 1:100 → 1:50), перезапустить —
    раскладка на листе пропорциональна (марки на тех же местах листа).
12. Арматура, «смотрящая в нас», с общими вложенными семействами: не маркируются
    ни родитель, ни вложенные (счётчик «Пропущено (смотрит в нас)»).
13. Повторный запуск: старые марки плагина удаляются, новые ставятся заново;
    ручные марки сохраняются.
14. Повторный запуск: выбранные ранее марки, высота зоны и положение текста
    восстановлены из пресета в окне 2.
15. 3D-вид не маркируется; вид, отсутствующий для сборки, — предупреждение в отчёт;
    элементы без позиции / невидимые / «смотрит в нас» — в счётчиках отчёта.
16. Ctrl+Z после выполнения — откат одним шагом (позиции и марки).
