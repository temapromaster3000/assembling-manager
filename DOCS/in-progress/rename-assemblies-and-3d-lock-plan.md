# План: блокировка 3D-видов + модуль «Переименовать сборки»

## Часть 1. Блокировка 3D-видов (правка первого модуля)

- 3D-вид блокируется сразу после создания и настройки (шаблон, рамка, фильтры), чтобы
  проектировщик не мог случайно изменить модель в виде.
- `ViewService`: новые методы `LockView`/`UnlockView` (для `View3D`:
  `SaveOrientationAndLock` / `RestoreOrientationAndLock` / `Unlock`, проверка `HasBeenLocked()`),
  оба с try/catch и логом.
- `OrchestratorService`: в цикле применения фильтров после `ApplyFilterToView`
  вызывать `LockView` для видов `View3D`.
- `ViewService.DeleteViewsByNames`: перед удалением снимать блокировку с `View3D`,
  иначе ранее заблокированный вид заменяется (Replace) с ошибкой.

## Часть 2. Модуль «Переименовать сборки» (переименовывает только виды)

## Сценарий
1. Проектировщик переименовывает сборку в проекте. Виды и спецификации сборки,
   значения параметра AssemblyParameter у элементов и фильтры остаются под старым именем.
2. Кнопка «Переименовать виды» на панели «Сборки»: модуль находит несоответствия
   и приводит имена видов и спецификаций под текущее имя сборки. Новые НЕ создаются —
   содержимое, аннотации и размеры сохраняются.
3. Листы модуль НЕ трогает (отдельный будущий модуль — см. `docs/future/sheets-rename-module-plan.md`).

## Определение переименования
- Сборка переименована, если хотя бы у одного из её элементов значение параметра
  AssemblyParameter отличается от текущего имени сборки. Старое имя = это значение.
- Если старое значение совпадает с именем существующей сборки — не обрабатываем
  (может быть чужой параметр), лог.

## Что делает модуль для каждой переименованной сборки
1. Переименовывает существующие виды и спецификации:
   `СтароеИмя + суффикс` → `НовоеИмя + суффикс`
   (суффиксы: `""`, `_Вид спереди`, `_Вид сзади`, `_Вид справа`, `_Вид слева`,
   3D `""`, `_Спецификация`). При занятом имени — пропуск с логом.
2. Обновляет значение AssemblyParameter у элементов на новое имя.
3. Обновляет фильтр спецификации сборки (`ScheduleFilterType.Equal` = новое имя) —
   иначе спецификация становится пустой.
4. Удаляет старые фильтры: `СтароеИмя_Фильтр`, `СтароеИмя_СкрытьЧужиеРазрезы`.
5. Создаёт новые фильтры с новым именем и новым значением правила;
   применяет к видам обновлённой сборки: фильтр сборки — ко всем видам,
   фильтр «СкрытьЧужиеРазрезы» — дополнительно к планам.
6. После коммита транзакции (вне её): `schedule.RefreshData()` для устаревших
   спецификаций + `doc.Regenerate()` — таблицы сразу показывают элементы.

## Отчёт
- Окно «Переименовано сборок: n» + список строк «Старое имя → Новое имя».

## Чек-лист ручной проверки (агент не может запустить Revit)
1. Сформировать виды для сборки, вручную переименовать сборку → запустить модуль:
   виды и спецификация переименованы, параметр у элементов = новое имя,
   фильтры пересозданы, отчёт: «Переименовано сборок: 1».
2. Аннотации/размеры, нанесённые на видах до переименования, сохранились.
3. Спецификация после переименования сразу показывает элементы (без ручного
   входа в настройки фильтра).
4. 3D-вид: сразу после формирования заблокирован (невозможно изменить модель);
   при согласии на замену вида (Replace) старый заблокированный корректно удаляется.
5. Повторный запуск модуля без изменений — «Несоответствий не обнаружено».
6. Производительность: плагин работает быстро (листы не обходятся).
7. Лента: панели «Сборки» и «Листы», кнопки на своих местах.
8. Ctrl+Z после модуля — всё откатывается одним шагом.
