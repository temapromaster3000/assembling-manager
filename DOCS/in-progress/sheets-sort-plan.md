# Модуль «Сортировка листов»

## Проблема

Плагин создаёт по листу на сборку. Проектировщик объединяет виды нескольких сборок на одном листе — пустые листы остаются и мешают; сборки могут переименовываться, а листы сохраняют старые имена. Если часть видов не поместилась, проектировщик добавляет лист в конец группы «под номером 20», хотя по имени сборки он должен идти сразу за листом 3.

## Цель

Модуль «Сортировка листов» для выбранной группы листов (как в диспетчере):

1. **Удаляет пустые листы** (нет ни одного размещённого вида и спецификации).
2. **Переименовывает листы** с видами только одной сборки — если имя листа не равно имени сборки и не содержит его (имя, содержащее имя сборки, например «Трубопровод_01 (начало)», считается ручным и не трогается).
3. **Перенумеровывает** оставшиеся листы: пользователь задаёт номер первого листа группы; порядок — по имени сборки (а не по текущему номеру).

## Поведение

### Окно модуля

- Дерево групп листов как в диспетчере; выбирается одна группа (или лист — работает группа над ним).
- Поле «Номер первого листа» (целое число).
- Сводка: «Группа «...»: листов — N, пустых — M».
- Кнопки «Отмена» / «Выполнить».

### Порядок очереди при перенумерации

Якорь листа:

- лист с видами одной сборки → имя этой сборки (например «Трубопровод_01»);
- лист с видами нескольких сборок → минимальное имя сборки из фактических («Трубопроводы 2-5» содержит виды сборок 2..5 → якорь «Трубопровод_02»);
- лист без распознанных видов (ручные чертежи) → первое число из имени листа («Трубопроводы 2-5» → якорь «Трубопроводы 2»).

Сортировка: сначала по числовому коду якоря (натурально), затем: лист с именем, точно равным якорю, раньше листов с приписками, затем по имени листа (натурально).

Перенумерация: первый лист очереди получает номер, введённый пользователем, дальше +1. Если номер занят листом вне группы — используется следующий свободный, в отчёте выводится предупреждение.

### После выполнения

Окно-отчёт:

- переименовано листов, удалено пустых, перенумеровано (список «старый → новый»);
- предупреждения (пропущенные занятые номера);
- время работы.

## Технические изменения

- `SheetService.IsSheetEmpty(doc, sheet)` — лист пуст, если нет `Viewport` и `ScheduleSheetInstance`.
- `Views/SheetsSortDialog.xaml(+cs)` — выбор группы листов + поле «Номер первого листа», сводка, валидация.
- `Views/SheetsSortReportDialog.xaml(+cs)` — отчёт.
- `Commands/SortSheetsCommand.cs`:
  - сбор анализа листов группы (пустые, базовые имена сборок из видов);
  - транзакция: удаление пустых → переименование → перенумерация (с двухфазной расстановкой номеров через временные, чтобы избежать конфликтов внутри группы);
  - логирование, отчёт.
- `App.cs` — кнопка «Сортировка листов» в панели «Листы».

## Ограничения

- Пустой лист определяется только по видам/спецификациям: тексты и прочие элементы листа не спасают его от удаления.
- Если на листе сборок нет совсем (только ручные виды) — лист не переименовывается, но участвует в перенумерации (якорь из имени листа).
- Редкий случай: смешанный лист покрывает диапазон кодов, один из которых есть отдельным листом — позиция смешанного листа определяется его минимальным кодом.
- Удалённые в модуле листы удаляются без страховки (только пустые).

## Контрольный список ручной проверки

1. Подготовить модель: создать виды для двух-трёх сборок, разместить на листах, оставить один пустой лист, переместить виды двух сборок на один лист (смешанный), добавить лист с видами одной сборки и ручным именем («Трубопровод_01 (начало)»).
2. Запустить модуль, выбрать группу листов.
3. Убедиться, что пустой лист удалился.
4. Убедиться, что лист с ручным именем («... (начало)») не переименован.
5. Убедиться, что лист «Лист 1» с видами одной сборки переименован в имя сборки.
6. Задать номер 10 — убедиться, что лист с видами следующей по алфавиту сборки (ранее номер 20) получил 11 и встал после листа 10.
7. Проверить, что смешанный лист «Трубопроводы 2-5» встал в очередь согласно минимальному коду.
8. Убедиться, что занятые вне группы номера пропускаются с предупреждением в отчёте.
9. Проверить отчёт: переименовано / удалено / перенумеровано (старый → новый) / предупреждения.
10. Проверить, что после отмены в главном окне ничего не изменилось.
