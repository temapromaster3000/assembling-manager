# Сортировка листов: причины сбоев в отчёте + оптимизация перезаписи

## Проблемы

1. Модуль сортировки листов при занятых листах пишет общее «Нумерация сбилась», не уточняя причину.
2. Модуль перенумеровывает все листы группы, даже те, у которых номер уже правильный
   (в логе: `from '7' to '7'`), плюс каждому листу сначала пишется временный номер. На больших
   моделях это лишние записи и долгая работа. Проверка занятости (checkout) тоже выполняется
   для всех листов группы сразу.

## Решения (согласованы)

- «Сбилась сортировка по имени» = имя листа не приведено к имени сборки (лист занят или
  переименование не удалось). «Сбилась нумерация» = номер не соответствует позиции в порядке
  сортировки. Возможны обе проблемы одновременно — в отчёте обе строки.
- Полная оптимизация: лишние записи номеров убираются, checkout — только для листов, которые
  реально нужно изменить.
- Пропуск занятых листов и резервирование их старых номеров — без изменений (как раньше).

## Реализация

### SortSheetsCommand.cs

1. **Проход 1 (без checkout):** идеальная нумерация по порядку сортировки с резервированием
   только номеров листов вне группы. Кандидаты на изменение = идеальный номер ≠ текущего
   ИЛИ требуется переименование (+ удаляемые листы/виды).
2. **Checkout только кандидатов** (`WorksharingService.CheckEditable`), затем итеративное
   уточнение: если занятые листы сдвинули план нумерации и появились новые «нуждающиеся»
   листы среди непроверенных — дополнительный точечный checkout (до 5 итераций).
3. **Проход 2:** занятые листы резервируют старые номера; финальные номера считаются тем же
   алгоритмом, что раньше (результат идентичен прежнему). Запись — только листам, у которых
   номер реально меняется; временные номера — тоже только им (защита от коллизий: временные
   значения проверяются против всех текущих номеров группы и внешних).
4. **Причины сбоев:** `numberingBreaks` (нумерация) и `nameBreaks` (имена ≠ имён сборок) —
   отдельные строки в предупреждениях отчёта; «Нумерация не сбилась…» — только если обе
   категории пусты. Переименование с ошибкой тоже попадает в «сортировку по имени».
5. **Статистика:** «Перенумеровано листов» — только реальные изменения; новая строка
   «Листов с актуальными номерами (без изменений): N».

### SheetsSortReportDialog.xaml.cs

- Новый параметр `unchangedCount` и строка статистики.

## Контрольный список ручной проверки (в Revit)

- [ ] Модель с уже верной нумерацией: отчёт показывает 0 перенумерованных, «без изменений: N»,
      работа заметно быстрее; в логе нет записей `from 'X' to 'X'`.
- [ ] Занятые листы: отчёт явно называет причину (нумерация / имена / обе); номера без дыр;
      после освобождения и повторного запуска всё выравнивается.
- [ ] Занятый лист с устаревшим именем → строка «Сортировка по имени сбилась».
- [ ] Удаление пустых/сигнальных листов, переименования — как раньше.
- [ ] Сборка Debug.R21 и Debug.R25 без ошибок.
