## Цель

Управлять сортаментами труб из Telegram обычным текстом: запрос → предпросмотр →
подтверждение кнопкой → применение. Позже — другие модули плагина.

Требования:

- бот работает только на компьютере пользователя;
- никаких открытых входящих портов;
- доступ только для разрешённых Telegram ID;
- запись в модель — только после подтверждения;
- выключатель записи в Revit остаётся вторым независимым предохранителем.

## Принятые решения (26.11.2026)

- **Готовый бот** `@grinev/opencode-telegram-bot` (v0.29.0, MIT), а не собственный:
  поддерживает OpenCode V2, long polling, whitelist и inline-кнопки разрешений.
- **Запись с кнопкой** в первой версии: предпросмотр → вопрос «Применить/Отмена» →
  `revit_apply_pipe_size_change`. Запрос разрешения opencode (`ask`) остаётся вторым
  предохранителем.
- **Только Revit-инструменты**: отдельный OpenCode-сервер песочницы, отдельная БД,
  конфиг и агент `revit`. Файлы, shell, веб и субагенты запрещены; встроенные агенты
  `build`/`plan`/`explore`/`general` отключены.
- **Ручной запуск**: `start-telegram-bot.bat` в отдельном окне; автозапуск не делаем.
- Токен и Telegram ID — в переменных окружения пользователя, не в git.

## Архитектура

```text
Telegram
   │  long polling (исходящие соединения)
   ▼
Бот @grinev/opencode-telegram-bot
   │  локальный HTTP API 127.0.0.1:49375
   ▼
Отдельный OpenCode-сервер песочницы
   │  XDG_CONFIG_HOME / XDG_DATA_HOME / XDG_STATE_HOME
   │  свой конфиг, БД, сессии и credentials opencode-go
   ▼
MCP-сервер Assembling Manager (stdio)
   │  именованный канал + токен
   ▼
MCP-мост в Revit
   │  ExternalEvent → TransactionGroup
   ▼
Revit API
```

- Бот запускается на этом же компьютере, где открыт Revit.
- Long polling: бот сам обращается к Telegram, входящие порты не открываются.
- Сервер песочницы слушает только `127.0.0.1`; основной opencode не затрагивается.
- `/opencode_stop` в боте останавливает только сервер песочницы.
- MCP-мост и выключатель записи — как в текущей реализации.

## Что реализовано

Скрипты и шаблоны в `tools/telegram-bot/`:

| Файл | Назначение |
|---|---|
| `setup-telegram-bot.bat` / `.ps1` | Установка бота, создание песочницы, конфиг, credentials, стартовая сессия |
| `configure-telegram-bot.bat` / `.ps1` | Токен BotFather и Telegram ID в переменные окружения |
| `start-telegram-bot.bat` / `.ps1` | Запуск сервера песочницы и бота в одном окне |
| `stop-telegram-bot.bat` / `.ps1` | Остановка сервера песочницы, если окно бота закрылось нештатно |
| `common.ps1` | Общие пути, health-check, запуск/остановка сервера, API |
| `templates/opencode.jsonc.template` | Конфиг песочницы: MCP `revit`, агент `revit`, запреты |
| `templates/AGENTS.md` | Инструкции агенту: статус, чтение, предпросмотр, вопрос, apply, ошибки |
| `README.md` | Инструкция для пользователя |

Пути на компьютере:

```text
%LOCALAPPDATA%\AssemblingManager\TelegramBot\
├── bot\.env                  # несекретные настройки бота
├── bot\settings.json         # проект, сессия, агент, модель
├── bot\logs\                 # логи бота
├── config\opencode\          # конфиг песочницы
├── data\opencode\            # БД, сессии, credentials песочницы
├── workspace\AGENTS.md       # инструкции агенту
├── logs\                     # логи OpenCode-сервера
└── server-password.txt       # пароль локального сервера
```

Особенности реализации:

- `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `XDG_STATE_HOME` уводят песочницу в отдельные
  папки; основной opencode и его сессии не видны.
- Credentials `opencode-go` экспортируются из основного opencode
  (`opencode auth export`) и импортируются в БД песочницы
  (`opencode auth import --server`). Временный файл экспорта удаляется.
- Песочница сама создаёт проект и стартовую сессию, а `bot\settings.json`
  сразу выбирает проект, сессию, агента `revit` и модель
  `opencode-go/deepseek-v4.1-flash`.
- Агент `revit` получает только инструменты `revit_*`; `revit_apply_pipe_size_change`
  требует разрешения (`ask`). Остальные действия запрещены, включая `execute`,
  `read`, `edit`, `shell`, `webfetch`, `websearch`, `subagent`, `skill`.
- Перед изменением агент обязан показать план и задать вопрос с кнопками
  «Применить» / «Отмена»; после «Применить» opencode показывает второе
  разрешение на `apply`. Повторный apply с тем же `previewId` даёт
  `PREVIEW_EXPIRED`.
- Скрипты запуска ждут не только `/api/info`, но и загрузку агента `revit`
  и подключение MCP-сервера (`Wait-SandboxReady`), иначе первый запрос может
  уйти до готовности инструментов.

## Безопасность

- Whitelist ID, режим «запрещено всё, кроме разрешённых».
- Токен только в переменных окружения пользователя; в git не попадает.
- OpenCode-сервер и бот — только `127.0.0.1`.
- Подтверждение перед записью — обязательно (вопрос + `ask` на apply).
- Выключатель записи в настройках плагина — второй предохранитель.
- В логах не хранить токен и личные сообщения (бот пишет служебные события).
- Отключение бота: `Ctrl+C`, `stop-telegram-bot.bat`, `/opencode_stop`.

## Открытые вопросы (закрыты)

- Готовый бот или собственный? — Готовый `@grinev/opencode-telegram-bot`.
- Первый этап только для чтения? — Нет, запись с кнопкой и двумя предохранителями.
- Хранить ли историю? — Обычные сессии OpenCode в песочнице, отдельного архива нет.
- Несколько одновременных запросов? — Очередь/steer бота, один текущий сеанс.
- Доступ вне домашней сети? — Через Telegram long polling; VPN не требуется,
  проброс портов не нужен. Защита — whitelist.

## Ограничения

- Не запускать несколько ботов на один токен одновременно.
- Не открывать webhook и входящие порты.
- Не давать боту доступ к файлам и shell за пределами задачи.
- После повторного входа в `opencode-go` в обычном opencode нужно повторно
  выполнить setup, чтобы обновить credentials песочницы.
- Если основной opencode переустановлен или сменил путь, setup нужно повторить.
