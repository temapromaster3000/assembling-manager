# План: единая политика категорий (источник — только сборки)

## Проблема

Категории фильтров и привязки параметра формировались по-разному в трёх модулях:

- «Сформировать виды» (`OrchestratorService`) — глобальный набор категорий всех сборок (правильно);
- «Переименовать виды» (`RenameAssembliesCommand`) — только категории своей сборки;
- «Добавить существующее» (`AssignExistingService`) — добавлял в фильтр и привязку параметра категории выбранных элементов, из-за чего фильтры «обрастали» категориями, которые при пересоздании сбрасывались основным модулем и модулем переименования.

## Решение: единая политика

**Источник категорий — только сборки.** Плагин проходит по всем сборкам, собирает все встретившиеся категории; этот набор используется для привязки параметра и всех фильтров.

### 1. `RenameAssembliesCommand.cs`

- В `Execute`, в цикле детекции (уже обходятся все сборки), накапливать `HashSet<Category> allCategories` — как в `OrchestratorService.cs:44-62`.
- `CreateAndApplyNewFilters`: глобальный набор вместо категорий своей сборки; `EnsureAssemblyFilter`/`EnsureSectionMarkFilter` вместо `Create...` (переиспользование фильтра, обновление правил «на месте», сохранение назначений видам); `AddMissingCategories(doc, parameterId, allCategories)`.
- Удаление старых фильтров (`oldName_Фильтр`, `_СкрытьЧужиеРазрезы`) — без изменений.

### 2. `AssignExistingElementsCommand.cs`

- После выбора элементов и сбора вложенных — свежий проход по всем сборкам: набор допустимых категорий.
- Деление выбранных (включая вложенные) на допустимые и запрещённые.
- Запрещённые → предупреждающее окно со списком категорий; эти элементы пропускаются, остальные добавляются. Если запрещены все — отмена.
- Безопасная `AddMissingCategories` по категориям сборок выбранным параметром (внутри транзакции).

### 3. `AssignExistingService.cs`

- Убрать: сбор категорий выбранных, их привязку к параметру и всю `UpdateAssemblyFilter` — фильтрами занимаются только «Сформировать виды» и «Переименовать виды».
- В `AssignExistingResult` — вместо полей фильтра данные о пропущенных категориях; поправить окно результата.

### 4. Инвариант видимости существующих

Скрытие возможно только при (категория в фильтре) И (значение ≠ имени сборки). Значения существующих всегда актуальны (правка `rename: update AssemblyParameter for external elements`), наборы категорий фильтров стабильны → существующие не могут пропасть ни при переименовании, ни при пересоздании видов.

## Контрольный список ручной проверки (в Revit)

1. Существующее категории, которой нет ни в одной сборке (например, трубы при сборках из стен) → окно-предупреждение, элемент не добавлен, допустимые элементы добавлены.
2. Существующее категории из сборок → добавляется как раньше, остаётся видимым.
3. «Переименовать виды» → существующее не пропало, фильтры/спецификация на новом имени.
4. Повторный «Сформировать виды» → существующее на месте, наборы категорий фильтров стабильны.
5. Вложенный элемент семейства с запрещённой категорией тоже пропускается, остальные записываются.
