# План: сохранение настроек видов при «Обновить», семантика «Оставить»/«Обновить»

## Проблема

Пользователи вручную настраивают виды (обрезка рамок, разворот разрезов, секущий бокс 3D).
Действие «Обновить» в основном модуле «Сформировать виды» вызывало `UpdatePlanViewGeometry`,
`UpdateSectionViewGeometry`, `Update3DViewGeometry` — рамки расширялись, секущий бокс 3D
отключался, ручные настройки терялись. Кроме того, значение параметра перезаписывалось всем
членам сборки при каждом запуске, а фильтры обрабатывались для всех сборок независимо от
выбранных действий.

## Новая семантика

- **«Оставить»** — вообще ничего не проверяет и не трогает (и геометрию, и данные).
- **«Обновить»** — проверяет новых членов сборки и записывает им значение параметра
  (только тем, у кого значение пустое или устарело), проверяет фильтры и привязку параметра
  на новые категории; геометрию вида не трогает.
- **«Заменить»** — пересоздаёт вид с новой геометрией; данные и фильтры также обновляются.
- **Создание новых видов** — как раньше: рамки строятся заново, данные и фильтры обновляются.

## Изменения

### 1. `ViewService.cs`

- Удалить `UpdatePlanViewGeometry`, `UpdateSectionViewGeometry`, `Update3DViewGeometry`.
- Удалить ставшие ненужными хелперы (проверить использование: `UnionBoundingBox`,
  `ExpandPlanViewRange`); сохранить всё, что нужно для создания видов.

### 2. `OrchestratorService.cs`

- `CreateOrReplaceView`: убрать параметр `updateExisting` и лямбды в шести местах вызова;
  ветка «Обновить» только логирует и увеличивает `UpdatedCount`.
- Для каждой сборки вычисляется `needsDataWork` до создания видов:
  - есть конфликты и все действия «Оставить», и ничего не создаётся → `false`;
  - есть хотя бы одно «Обновить»/«Заменить» или будут создаваться новые виды (отсутствующие,
    не отложенные пользователем в `SkipItems`) → `true`.
- При `needsDataWork = true`: запись значения параметра только устаревшим/новым членам;
  `EnsureAssemblyFilter`/`EnsureSectionMarkFilter` как сейчас; при `needsDataWork = false`
  сборка пропускается целиком.
- `AddMissingCategories` — глобально, но только если хотя бы одной сборке нужна работа с данными.

### 2a. `ParameterService.cs`

- Новый метод `FindElementIdsWithOutdatedParameterValue(doc, parameterId, elementIds, value)`:
  перебор членов сборки, возврат Id тех, у кого параметр отсутствует или `AsString() != value`.

### Не меняется

- Ветка «Обновить» для спецификаций — фильтр спецификации обновляется (это данные).
- Модуль «Переименовать виды» — там своя запись значений и Ensure-фильтры.

## Контрольный список ручной проверки (в Revit)

1. Настроить виды вручную (обрезать план, развернуть разрез, секущий бокс 3D) → «Сформировать
   виды», все «Оставить» → ничего не изменилось.
2. То же, но «Обновить» → геометрия не изменилась; новые члены сборки получили значения и
   видимы; при появлении новой категории фильтр/привязка обновились.
3. Новые члены сборки при всех «Оставить» → значения не записываются (элементы скрыты на
   сохранённых видах, пока не выбрать «Обновить») — ожидаемое следствие семантики.
4. «Заменить» → вид пересоздаётся с новой геометрией, данные обновлены.
5. Спецификация «Обновить» → фильтр проверен/обновлён.
