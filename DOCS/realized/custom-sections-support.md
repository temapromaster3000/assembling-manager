# План: поддержка пользовательских разрезов (префикс «имяСборки_»)

## Проблема

Пользователи создают дополнительные разрезы для больших схем трубопроводов, называя их
с именем сборки (например, «СБ-01_Узел А»). Плагин не обрабатывает такие разрезы:
модули группы «Оформление» («Проставить позиции», «Ближайшие оси», «Оси трубопроводов»)
находят только свои 4 разреза по жёстким суффиксам, а «Переименовать виды» их не
переименовывает и не назначает фильтр.

## Решения (согласованы с пользователем)

- Правило принадлежности разреза сборке: **имя начинается с «имяСборки_»** (как фильтр
  «СкрытьЧужиеРазрезы» — нет ложных срабатываний на похожие имена «СБ-01» / «СБ-011»).
- Пользовательские разрезы включаются в переименование.
- Фильтр сборки: единообразно с разрезами плагина — при переименовании старый фильтр
  удаляется, новый назначается своим видам и пользовательским разрезам.
  В «Сформировать виды» фильтр на пользовательские разрезы НЕ назначается (пользователь
  назначает сам).

## Изменения

### 1. `ViewService.cs`
Новый метод `GetAssemblySectionsByPrefix(doc, assemblyName)`: все `ViewSection`, имя
которых начинается с `assemblyName + "_"` (Ordinal, без шаблонов, сортировка по имени).
Включает и свои 4 разреза плагина — их имена тоже начинаются с префикса.

### 2. Группа «Оформление»
- `TagService.cs` (2 места, ~539-542 и ~1077-1080): планы из `GetExistingAssemblyViews`
  (`is ViewPlan`), разрезы — префиксный поиск.
- `NeighborAxesService.cs` (~165-203): перебор 4 суффиксов → префиксный поиск; план по
  точному имени — как сейчас.
- `PipeAxisService.cs` (~118-155): то же; 3D для проверки перекрытий — без изменений.

### 3. `RenameAssembliesCommand.cs`
- После переименования своих видов — доп. проход: пользовательские разрезы со старым
  префиксом → `новоеИмя + остаток имени` (try/catch; свои разрезы к этому моменту уже
  переименованы и не попадают).
- `CreateAndApplyNewFilters`: цели назначения фильтра = свои виды (6 точных имён) +
  пользовательские разрезы (префиксный поиск), объединение без дублей по `Id`;
  `_СкрытьЧужиеРазрезы` — только планам, как сейчас.

### Не меняется
- «Сформировать виды» — пользовательские разрезы не трогает.
- «Разместить на листах» / «Сортировка листов».

## Контрольный список ручной проверки (в Revit)

1. Пользовательский разрез «имяСборки_Узел 1» обрабатывается всеми тремя модулями
   «Оформления» (позиции/марки, ближайшие оси, оси трубопроводов).
2. Переименование сборки → пользовательский разрез переименован и получил новый фильтр.
3. Похожие имена сборок (СБ-01 / СБ-011) не пересекаются.
4. Свои 4 разреза и остальные модули — без регрессий.
5. «Сформировать виды» пользовательские разрезы не трогает.
