# План: скрытие чужих меток разрезов на планах сборок

## Цель
На каждом сгенерированном плане сборки скрывать метки разрезов, которые относятся к другим сборкам или не принадлежат текущей сборке.

## Решение
Использовать видовой фильтр по категории **«Разрезы»** (`BuiltInCategory.OST_Sections`) и параметру **«Имя вида»** (`BuiltInParameter.VIEW_NAME`).
Правило фильтра: **«Имя вида не содержит `<assemblyName>_`»**.  
Нижнее подчёркивание в конце нужно, чтобы отличать сборки с похожими именами (например, `Маторин` и `Маторин_2`).

Пользователь проверил этот подход вручную в интерфейсе Revit — он работает.

## Шаги реализации

1. **`FilterService.CreateSectionMarkFilter`**
   - Принимает `Document` и имя сборки.
   - Создаёт `ParameterFilterElement`:
     - категория — `OST_Sections`;
     - параметр — `VIEW_NAME`;
     - правило — `CreateNotContainsRule` для `<assemblyName>`;
     - имя фильтра — `<assemblyName>_СкрытьЧужиеРазрезы`.
   - Перед созданием удаляет существующий фильтр с таким именем.

2. **Применение фильтра в `OrchestratorService.GenerateViews`**
   - После создания/дублирования плана сборки применять фильтр меток разрезов.
   - Применять только к планам (`view is ViewPlan`).
   - Для совместимости со старыми Revit использовать условную компиляцию (`REVIT2023_OR_GREATER`) при создании правила.

3. **Создание видов разрезов «с нуля»**
   - Для разрезов (`Вид спереди`, `Вид сзади`, `Вид справа`, `Вид слева`) не использовать дублирование от первого созданного вида.
   - Причина: дублирование вида разреза копирует метку разреза в координатах исходного вида, и через API её нельзя корректно сместить к текущей сборке.
   - В `OrchestratorService` для видов разрезов передавать `master = null` и не сохранять их в `viewMasters`.

4. **Использование всех категорий в фильтре сборки**
   - Вместо категорий элементов конкретной сборки передавать в `CreateAssemblyFilter` общий набор `allCategories`.
   - Это гарантирует, что фильтр сборки будет содержать все категории, встречающиеся в любой сборке.

5. **Исправление отображения `ADSK_Группирование`**
   - В `MainWindow.xaml` заменить `ADSK_Группирование` на `ADSK__Группирование`.
   - В WPF одиночный `_` в `Content` используется как акселератор клавиатуры, поэтому он не отображается.

## Ручная проверка

- [ ] Запустить плагин в Revit 2021 и создать виды для нескольких сборок.
- [ ] На плане каждой сборки убедиться, что чужие метки разрезов скрыты.
- [ ] Убедиться, что собственные метки разрезов сборки остаются видимыми.
- [ ] Проверить, что фильтр сборки по-прежнему скрывает элементы других сборок.
- [ ] Проверить, что в окне плагина параметр отображается как `ADSK_Группирование`.
- [ ] Собрать конфигурации `Debug.R21` и `Debug.R25` без ошибок.
