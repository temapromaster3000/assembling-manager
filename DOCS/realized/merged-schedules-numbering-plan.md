# Модуль «Проставить позиции» — объединение спецификаций (сквозная нумерация)

## Идея

Несколько сборок может находиться на одном листе; спецификация такого листа
собирается из нескольких маленьких спецификаций. Для объединённых спецификаций
идентичные элементы должны получать **одну и ту же позицию**: если в спеке 1
есть «труба 1» и в спеке 2 есть «труба 1» — обе строки получают позицию,
записанную первой.

Реализуется в существующей кнопке «Проставить позиции» — в окне 1 появляется
галка «Объединить спецификации».

## Поведение

### Галка «Объединить спецификации» (окно 1)
- Расположена в нижней панели, рядом со сводкой.
- Активна только когда выбрано **больше одной** спецификации; при 0/1 — снята
  и неактивна (автоматически, в `UpdateSummary`).
- **Никогда не сохраняется в пресет** — при каждом открытии окна выключена,
  даже если в прошлый раз её включали.
- Выключена → обычный режим: каждая спецификация нумеруется с 1 (как раньше).

### Сквозная нумерация (галка включена)
- Спецификации обрабатываются по порядку списка (сверху вниз).
- Спека 1 — как обычно: группы → позиции с 1.
- Для каждой группы спеки N:
  1. Проверка ключевых слов (как раньше): пропущенная группа не получает номер
     и не сдвигает счётчик.
  2. Идентичность: значение `ADSK_Наименование` группы (первое непустое
     значение среди элементов группы; Trim, сравнение без учёта регистра).
     Если в уже обработанных спеках есть такое наименование — присваивается
     существующий номер (счётчик не растёт).
  3. Иначе — новый номер: `последний использованный + 1`, наименование
     записывается в карту. Счётчик глобальный по всем выбранным спецификациям
     и не обнуляется между ними: если в спеке 1 десять позиций, первая
     уникальная строка спеки 2 получает позицию 11.
- Правила:
  - ключ — **только `ADSK_Наименование`**, остальные столбцы не сравниваются
    (в разных спеках значения других столбцов могут различаться);
  - группа с пустым/отсутствующим наименованием **не склеивается никогда** —
    всегда новый номер (не попадает в карту);
  - если параметра `ADSK_Наименование` нет в модели — объединение невозможно:
    предупреждение в лог и автоматический откат в обычный режим;
  - порядок групп внутри спеки, сортировка, пропуск по ключевым словам,
    missing-логи — без изменений.
- Этап 2 (марки) не меняется: марки читают позицию из элементов.

### Отчёт
- При включённом объединении в итоговый отчёт добавляется строка
  «Объединение спецификаций: включено»; в логе — переиспользовано X позиций,
  новых Y.

  - если `nameParameterId == null` и объединение включено — предупреждение,
    состояние не создаётся (обычный режим);
  - строка отчёта «Объединение спецификаций: включено».

## Контрольный список ручной проверки

1. Две спецификации с одинаковыми элементами (галка включена): у одинаковых
   наименований — одна и та же позиция; уникальные продолжают счёт без дыр.
2. Три спецификации: третья находит совпадения и в первой, и во второй.
3. Ключевые слова: пропущенная группа не получает номер и не сдвигает
   нумерацию последующих групп.
4. Галка: активна только при выбранном количестве спецификаций больше одного;
   после повторного открытия окна — всегда выключена; пресет проекта не
   меняется.
5. Выключенная галка: нумерация каждой спецификации с 1 — как раньше.
6. Элементы с пустым/отсутствующим `ADSK_Наименование`: каждая такая группа
   получает отдельный новый номер (без склейки).
7. Позиции записаны в элементы; этап 2 (марки) показывает номера как раньше;
   Ctrl+Z — откат одним шагом.
8. В отчёте при включённой галке — строка «Объединение спецификаций: включено».
