# Рефакторинг: выбор параметра для фильтра

## Статус

Implemented.

## Цель

Зафиксировать параметр `ADSK_Группирование` для фильтра видов. Пользователь выбирает: использовать существующий параметр или создать новый с именем `AssemblyParameter`. Без возможности выбирать разные параметры между запусками.

## Поведение

В `MainWindow` добавлен информационный блок с двумя `RadioButton`:

- **Использовать "ADSK_Группирование"**
  - Плагин проверяет, существует ли параметр с таким именем.
  - Показывает в строке состояния:
    - Параметр найден / не найден.
    - Все ли категории элементов сборок привязаны.
    - Сколько элементов уже имеют заполненное значение.
  - Если параметр не найден — кнопка «Сформировать» блокируется.
- **Создать новый пользовательский параметр**
  - Пишет в строке состояния: «Будет создан общий параметр с именем AssemblyParameter».
  - Кнопка «Сформировать» активна без валидации.

### UI

- Окно фиксированного размера (`ResizeMode="NoResize"`).
- Группа «Параметр для фильтра» имеет фиксированную высоту `150` и содержит `ScrollViewer` для длинного статуса.
- Все сообщения статуса отображаются оранжевым цветом.
- Символ подчёркивания в `ADSK_Группирование` отображается корректно через двойное подчёркивание в XAML (`ADSK__Группирование`).
- Разрезы выбираются в `Popup` под стрелкой, без кнопок OK/Cancel. Стрелка — `Path` с треугольником, выровнен с чекбоксом «Разрезы».

## Изменения в коде

### 1. `ViewCreationOptions`

- Убран `SelectedParameterName`.
- Добавлены:
  - `bool UseExistingGroupingParameter` — использовать `ADSK_Группирование`.
  - `bool CreateNewParameter` — создать `AssemblyParameter`.

### 2. `ParameterService`

- Восстановлен `GetOrCreateParameter` (создание `AssemblyParameter` через временный ФОП).
- Оставлен `GetParameterByName` для поиска `ADSK_Группирование`.
- Оставлены `ValidateParameterCategories` и `CountExistingValues`.

### 3. `OrchestratorService`

- Если `UseExistingGroupingParameter` — искать `ADSK_Группирование`, бросать исключение если не найден.
- Если `CreateNewParameter` — создавать/находить `AssemblyParameter` через `GetOrCreateParameter`.

### 4. `MainWindow.xaml`

- Убран `ComboBox` выбора параметра.
- Добавлен `GroupBox` «Параметр для фильтра» с двумя `RadioButton` и `ScrollViewer` для статуса.
- Добавлен `Popup` с 4 `CheckBox` для выбора разрезов.
- Добавлена кнопка-стрелка (`Path`) для открытия `Popup`.

### 5. `MainWindow.xaml.cs`

- При смене выбора `RadioButton` обновляется статус и валидация.
- При выборе `ADSK_Группирование` — валидируется существование и привязка категорий.
- При выборе создания — показывается информационный текст.
- Обработчик стрелки переключает `Popup.IsOpen`.

### 6. `CreateAssemblyViewsCommand`

- Собирает категории и элементы сборок, передаёт в `MainWindow`.

## Контрольный список ручной проверки

- [x] Сборка проходит для `Debug.R24` и `Debug.R25`.
- [ ] При выборе `ADSK_Группирование` и его отсутствии — кнопка заблокирована, статус показывает «не найден».
- [ ] При выборе `ADSK_Группирование` и его наличии — показываются непривязанные категории и заполненные значения.
- [ ] При выборе создания нового параметра — показывается текст о создании, кнопка активна.
- [ ] Виды создаются с правильным параметром в фильтре.
- [ ] Повторный запуск не дублирует параметр.
- [ ] Popup разрезов открывается по стрелке, закрывается по клику вне и повторной стрелке.
- [ ] Строка «Будет перезаписано значений: n» показывается только при n > 0.
- [ ] Список непривязанных категорий показывается только если есть такие категории.
