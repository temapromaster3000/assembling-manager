# План оптимизации создания видов через копирование от первой реальной сборки

## Статус

`realized` — план реализован и запушен на GitHub.

## Проблема

Плагин создаёт виды (план, 4 разреза, 3D) для каждой сборки (`AssemblyInstance`).
На большом проекте (50+ сборок, ~500 видов) создание видов занимает заметную часть общего времени.

Джереми Таммик и практика на форумах Revit API указывают, что **`View.Duplicate(ViewDuplicateOption.Duplicate)` заметно быстрее, чем `CreatePlanView` / `CreateSection` / `CreateIsometric`**, потому что дублирование обходит полную генерацию графики вида с нуля.

## Цель

Сократить время фазы создания видов, заменив повторное создание каждого вида с нуля на дублирование уже созданного вида той же категории.

## Идея

Вместо отдельных временных мастер-видов:

1. Обрабатываем сборки по порядку.
2. **Первый реально созданный вид** каждого типа (план, фасад спереди, фасад сзади, вид справа, вид слева, 3D) становится мастером для этого типа.
3. Все остальные виды того же типа создаём через `View.Duplicate(ViewDuplicateOption.Duplicate)` от этого мастера.
4. После дублирования переименовываем вид и подгоняем `CropBox` / `SectionBox` / `ViewRange` под текущую сборку.
5. Удалять мастер-вид не нужно — он остаётся как обычный вид первой реально созданной сборки.

## Алгоритм

- В `OrchestratorService` вести словарь: `Dictionary<ViewType, View> _masters`.
- Для каждой сборки и каждого выбранного типа вида:
  - Если вид нужно **пропустить** — пропускаем.
  - Если вид нужно **создать или заменить**:
    - Если мастер для этого типа уже есть → дублируем его, переименовываем, подгоняем рамку.
    - Если мастера ещё нет → создаём вид с нуля текущей логикой и сохраняем как мастер.
- Если `CanViewBeDuplicated` вернул `false` → **fallback** на создание с нуля.

## Изменения

### 1. `ViewService`

Добавить методы:

```csharp
public ViewPlan DuplicatePlanView(ViewPlan source, string newAssemblyName, BoundingBoxXYZ bbox, ElementId levelId);
public ViewSection DuplicateSectionView(ViewSection source, string newAssemblyName, BoundingBoxXYZ bbox, ...);
public View3D Duplicate3DView(View3D source, string newAssemblyName, BoundingBoxXYZ bbox);
```

Каждый метод:

1. Проверяет `source.CanViewBeDuplicated(ViewDuplicateOption.Duplicate)`.
2. Вызывает `source.Duplicate(ViewDuplicateOption.Duplicate)`.
3. Получает новый вид по Id, меняет `Name`.
4. Заменяет `CropBox` / `SectionBox` / `ViewRange` под новую сборку.
5. Возвращает вид.

Старые методы `CreatePlanView` / `CreateFrontView` / `CreateBackView` / `CreateRightView` / `CreateLeftView` / `Create3DView` остаются как fallback.

### 2. `OrchestratorService`

- В `GenerateViews` добавить словарь `_masters`.
- При создании/замене вида:
  - если мастер для типа уже есть — вызвать соответствующий `Duplicate...`;
  - если нет — создать с нуля и сохранить в `_masters`.
- Применение шаблонов и фильтров остаётся без изменений: сначала все виды, потом шаблоны, потом фильтры.

## Риски

- **Первая сборка может быть пропущена.** Тогда мастер для этого типа создастся при первой же сборке, где вид реально создаётся. Это нормально — просто первая «непропущенная» сборка платит полную цену создания.
- **Первая сборка может быть заменена.** Старый вид удаляется, новый создаётся с нуля и становится мастером. Ок.
- **Дублирование может не сработать.** Оставляем fallback на старое создание.
- **Шаблон вида может контролировать `CropBox`.** Проверяем на тестовом проекте. Если так, настройка рамки после дублирования может не сработать.
- **Дублирование может скопировать лишние настройки.** Мастер-вид создаётся без фильтров и с минимальными настройками; шаблон применяется отдельно позже.
- **Revit API однопоточный.** Параллелить нельзя.

## Ручная проверка

- Маленький проект (2–5 сборок): корректность имён, рамок и фильтров.
- Большой проект (50+ сборок): сравнить время фазы создания видов до и после.
- Проверить fallback: временно отключить дублирование для одного типа вида и убедиться, что старое создание всё ещё работает.
- Проверить случай, когда первая сборка пропускается или заменяется.
