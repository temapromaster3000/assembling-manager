## Цель

Добавить на ленту группу `Трубы` и первый модуль `Сортаменты`, который позволяет просматривать все `PipeSegment` активного документа, редактировать каталог размеров и применять изменения к трубам без ручного выбора каждой трубы.

## Зафиксированные решения

- В выпадающем списке отображаются все `PipeSegment` активного документа, включая неиспользуемые.
- Область переноса — все трубы активного документа, использующие выбранный старый сегмент.
- Для существующей строки редактируются только наружный диаметр и толщина стенки.
- Номинальный диаметр существующей строки не редактируется; новая строка создаётся с новым DN.
- Внутренний диаметр вычисляется только для отображения: `Dвнутр = Dнаружн − 2 × толщина`.
- Размеры отображаются и вводятся в единицах текущего проекта.
- Номинальный диаметр первого столбца всегда только для чтения; добавление выполняется через отдельный диалог ввода DN.
- Переключение между сегментами не спрашивает подтверждение и сохраняет изменения в черновиках.
- Кнопка `Применить` собирает все изменённые сегменты и применяет их одной транзакцией; `Отмена` удаляет все черновики.
- Удаление DN, используемого трубами, блокируется сообщением без списка труб.
- Фитинги, изоляция и другие MEP-элементы не изменяются.
- При любом изменении каталога сначала выполняется попытка скопировать исходный `PipeSegment` с `UseDestinationTypes`.
- Если Revit сохраняет исходный `MaterialId`, каталог изменяется на копии; для сегментов без материала копирование остаётся единственным способом.
- Если Revit дублирует материал, попытка копирования откатывается в `SubTransaction`, а для материального сегмента создаётся replacement через `PipeSegment.Create` с исходным `MaterialId` и новой Спецификацией/Типом.
- Исходный материал никогда не создаётся и не заменяется; описание, шероховатость, размеры и флаги сохраняются.
- После переноса труб и обновления Routing Preferences старый сегмент удаляется.
- Сначала выполняется попытка вернуть старому сегменту исходное имя через API.
- Если это невозможно, используется следующий свободный суффикс: `Исходное1`, `Исходное2` и далее.
- Повторный цикл создания сегмента и повторного переноса труб не выполняется.
- В отчёте всегда показывается итоговое имя сегмента.

## Техническая схема

### Чтение

1. Собрать `PipeSegment` через `FilteredElementCollector`.
2. Для каждого сегмента считать `MaterialId`, `ScheduleTypeId`, `Description`, `Roughness` и `GetSizes()`.
3. Считать использование сегмента всеми `Pipe` документа через параметр `RBS_PIPE_SEGMENT_PARAM`.
4. Для каждой трубы читать `RBS_PIPE_DIAMETER_PARAM` и сопоставлять его с `MEPSize.NominalDiameter`.

### Применение

1. Валидировать строки, единицы, формулу внутреннего диаметра и уникальность DN.
2. В безопасной `SubTransaction` выполнить `CopyElements` с `UseDestinationTypes`.
3. Проверить, что копия сохранила `MaterialId` (в том числе `InvalidElementId`) и исходный каталог.
4. Если материал сохранился, изменить размеры на копии через `RemoveSize`/`AddSize` с регенерациями.
5. Если Revit создал новый материал, откатить копирование и для материального сегмента использовать `PipeSegment.Create` с исходным `MaterialId` и новой Спецификацией/Типом.
6. Для сегмента без материала при невозможности копирования остановить операцию без изменения модели.
7. Скопировать описание и шероховатость.
8. Заменить ссылки на старый сегмент в Routing Preferences всех затронутых `PipeType`.
9. Перевести трубы на новый сегмент через `RBS_PIPE_SEGMENT_PARAM`.
10. Назначить каждой трубе точный `NominalDiameter` из нового списка.
11. Выполнить регенерацию и проверить сегмент, диаметр, материал и отсутствие read-only параметров.
12. Удалить старый сегмент только после успешной проверки.
13. Вернуть исходное имя новому сегменту; при невозможности использовать следующий свободный суффикс.
14. Не создавать, не дублировать и не удалять исходный материал.

Все изменения выполняются в `TransactionGroup` и `Transaction`; при ошибке выполняется полный откат.

## Интерфейс

- Группа ленты: `Трубы`.
- Кнопка: `Сортаменты`.
- Верхний список: все сегменты.
- Таблица:
  - номинальный диаметр;
  - наружный диаметр;
  - толщина стенки;
  - внутренний диаметр.
- Кнопки: `Добавить размер`, `Удалить размер`, `Применить`, `Отмена`.
- Внутренний диаметр не редактируется.
- Для существующего DN изменяемые поля — OD и толщина стенки.
- Для новой строки DN, OD и толщина вводятся пользователем.
- Информационная строка показывает `Спецификация/Тип` по имени текущего каталога без префикса материала, только если материал назначен; для сегмента без материала имя остаётся полным.
- Размеры, используемые трубами, выделяются светло-красным во всех четырёх столбцах и получают tooltip; кнопка удаления блокируется при их выборе.
- Все кнопки имеют одинаковую высоту и скругление; `Применить` сохраняет primary-оформление, остальные кнопки нейтральные.
- Четыре колонки таблицы имеют пропорциональную ширину; минимальная ширина окна вычисляется по заголовкам и фактическим значениям, горизонтальная прокрутка отключена.
- Значения всех столбцов выровнены по вертикали; внешняя рамка нередактируемых ячеек — 1 px, редактируемых — 2 px, внутренняя рамка текстового поля отсутствует.
- Обычная выбранная строка получает светло-синий фон, а используемый DN при выборе остаётся красным.
- При переключении сегментов изменения сохраняются в памяти и не требуют подтверждения.
- Кнопка `Применить` обрабатывает все изменённые сегменты одной транзакцией и формирует общий отчёт только с количеством изменённых сегментов, добавленных, изменённых и удалённых размеров.
- В успешном отчёте не выводятся детали по отдельным сегментам и предупреждения; диагностика остаётся в логе.

## Критерии готовности

- Все сегменты документа отображаются в выпадающем списке.
- Таблица показывает значения в единицах проекта.
- Внутренний диаметр пересчитывается автоматически.
- Неиспользуемый DN можно добавить через отдельный диалог, изменить и удалить; DN в таблице только для чтения.
- Изменения нескольких сегментов сохраняются при переключении и применяются одной транзакцией; отмена не меняет модель.
- Используемый DN нельзя удалить: строка подсвечивается, tooltip объясняет причину, кнопка удаления блокируется.
- Любое изменение каталога не оставляет старый сегмент в модели.
- Трубы после операции используют копию сегмента и правильный номинальный размер.
- Новые трубы получают копию сегмента через Routing Preferences.
- Исходный материал не дублируется и не удаляется; сегменты без материала сохраняют это состояние.
- При любой ошибке модель не изменяется частично.
- Операция корректно работает в R21–R25.
- Успешный отчёт содержит только четыре агрегированных числа, а при ошибке показывается сообщение и состояние отката.

## Диагностическое логирование

Лог запуска содержит:

- уникальный `operationId`, путь и версию загруженной DLL, версию Revit и документ;
- список найденных `PipeSegment`, их `ElementId`, `MaterialId`, материал, Спецификацию/Тип и количество труб;
- исходные и заданные `DN/OD/ID/толщина` в единицах Revit;
- `copy attempt`, возвращённые `ElementId` и найденный новый `PipeSegment`;
- состояние материала и Спецификации/Типа до и после копирования;
- откат неудачной копирующей попытки и переход к fallback с исходным материалом;
- удаление/добавление размеров на копии и регенерации;
- перенос каждой трубы и заменённые правила Routing Preferences;
- повторное чтение каталога после копирования/fallback и после переноса труб, количество несовпадений;
- проверку совпадения `MaterialId` нового сегмента с исходным;
- статусы Transaction/TransactionGroup, rollback и итоговое имя сегмента.

Путь лога: `%APPDATA%\Autodesk\Revit\Addins\AssemblingManager\Logs\assembling-manager-*.log`.
