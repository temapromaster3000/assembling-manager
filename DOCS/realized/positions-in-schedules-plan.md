# Модуль «Проставить позиции» (этап 1 оформления)

## Идея

Третья группа ленты «Оформление». Первый модуль — автоматическое заполнение номеров
позиций в спецификациях сборок. Этап 2 (марки на видах) — впереди, отдельным решением.

Пользователь вручную выбирает спецификации (уже заполненные проектировщиком не трогаем),
задаёт ключевые слова — строки, чей элемент содержит ключевое слово в параметре
`ADSK_Наименование`, остаются без позиции.

## Поведение

### Окно модуля

- Левая часть — «Ключевые слова (пропуск строк)»: список полей (по умолчанию одно),
  кнопки «+ Добавить» / «− Удалить» (удаляет активное поле, иначе последнее).
- Правая часть — дерево спецификаций как в диспетчере (группы по браузер-организации,
  все доступные нешаблонные спецификации):
  - выбор листа: клик — один; Ctrl+клик — добавить/убрать; Shift+клик — диапазон
    по порядку листьев дерева (кастомная подсветка);
  - поиск по имени спецификации фильтрует дерево, выбранные не теряются;
  - сводка «Выбрано спецификаций: N. Ключевых слов: K»;
  - кнопка «Выполнить» активна при ≥1 выбранной спецификации.
- После выполнения — отчёт: «Обработано спецификаций: N», «Пропущено спецификаций: M»,
  «Время работы». Подробности причин — в лог-файле.

### Обработка спецификации

1. Если в определении спецификации нет поля `ADSK_Позиция` → спецификация пропускается
   (лог: причина), команда не падает.
2. Группируем элементы коллектора спеки по полям группировки (см. ниже) — каждая
   группа = строка спецификации (в т.ч. объединённая из N одинаковых элементов).
3. Пропуск строк: если хотя бы у одного элемента группы в `ADSK_Наименование`
   встречается ключевое слово — вся строкa без позиции (счётчик skipped).
4. Остальные группы нумеруются 1..N по порядку (сортировка/группировка самой спеки),
   номер записывается в `ADSK_Позиция` ВСЕМ элементам группы.
5. Если параметра `ADSK_Наименование` нет в проекте — ключевые слова не применяются
   (предупреждение в лог), позиции проставляются всем строкам.
6. Одна транзакция + FailurePreprocessor; RollBack при ошибке. После записи —
   `RefreshData()` по обработанным спецификациям.
7. Повторный запуск по выбранным спецификациям перезаписывает значение с 1.

## Технические изменения

Сопоставление строк и элементов — через поля группировки самой спецификации
(прямой «элемент по строке» API не существует, решение подтверждено рекомендациями
Джереми Таммика и практикой форума Autodesk):

- `ScheduleDefinition.GetSortGroupFields()` — поля группировки (+ SortOrder);
  если групповых полей нет — берутся все поля-параметры, кроме «Поз.»;
- элементы — коллектор по виду спецификации (`FilteredElementCollector(doc, schedule.Id)`,
  без типов и материалов);
- кортеж значений полей у элемента: `LookupParameter(имя поля)`; для типовых значений
  (обозначение/марка) — из элемента типа (`doc.GetElement(element.GetTypeId())`);
- одинаковый кортеж = одна строка спецификации (группа, в т.ч. неайтемизированная из
  N одинаковых элементов); каждая группа получает один номер позиции (1..N по порядку
  группировки+сортировки спеки);
- пропуск по ключевым словам: строка (группа) целиком без позиции, если ХОТЯ БЫ ОДИН
  элемент группы содержит ключ в «ADSK_Наименование»;
- после записи — `RefreshData()` по обработанным спецификациям;
- дерево спецификаций окна: пустые подпапки браузер-организации (имя «???») не
  отображаются — спецификации поднимаются к содержательным папкам (как показывает
  диспетчер).

- `BrowserGroupService` — новый `ScheduleGroupNode` + `BuildScheduleTree(doc)`:
  дерево доступных спецификаций по браузер-организации видов;
- `ScheduleService.IsAvailableSchedule` — стал public static (используется в дереве);
- `Views/AssignPositionsDialog.xaml(+cs)` — окно (ключевые слова + дерево с кастомным
  мультивыбором и поиском; `ScheduleTreeNode`-VM с `INotifyPropertyChanged`);
- `Commands/AssignAssemblyPositionsCommand.cs` — команда с группировкой по полям спеки;
- `Services/PositionPresetStorage.cs` — пресет ключевых слов через ExtensibleStorage
  (DataStorage-элемент, схема `AssemblingManagerPositionKeywordsPreset`): сохраняется в RVT,
  невидим в UI, общий параметр не используется;
- `App.cs` — панель «Оформление», кнопка «Проставить позиции».

## Контрольный список ручной проверки

1. Открыть модель со спецификациями сборок (поле `ADSK_Позиция` и `ADSK_Наименование`).
2. Запустить модуль, выбрать несколько спецификаций (Ctrl и Shift), ввести одно
   ключевое слово и добавить второе через «+».
3. «Выполнить» → в отчёте N обработано, M пропущено, время.
4. Проверить: номер с 1 по порядку строк; строки с ключевым словом в
   `ADSK_Наименование` — без позиции.
5. Выбрать спецификацию без поля позиции → она в «пропущено», остальные обрабатываются.
6. Поиск по дереву: фильтр работает; выделенные не сбрасываются.
7. Повторный запуск — перезапись с 1, Ctrl+Z — откат одним шагом.
