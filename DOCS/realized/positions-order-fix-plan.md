# План: исправление сортировки позиций (v9)

## Статус

In progress.

## Проблема

Модуль «Проставить позиции» нумерует группы 1..N, повторяя сортировку
спецификации. Ошибка была в сравнении: Revit сортирует ТЕКСТ с учётом чисел
внутри него (натуральная сортировка), а плагин сравнивал текст как текст.
Доказано дампом таблицы (лог 2026-09-11): «Труба о89» раньше «Труба о108»,
«Заглушка 80» раньше «Заглушки 100», «DN80» раньше «DN200», «M16x85» раньше
«M16x120» — обычное текстовое сравнение даёт обратный порядок. Отсюда ряды
номеров вида `1 2 4 3 5 6 7 12 8 9 10 11 14 13 15`.

## Решение

1. **Откат чтения таблицы** (версии v2–v6): удаляются `TryGetTableRowOrder`,
   `GetRowMatchColumns`, `RowMatchColumn`, `GroupMatchesRow`,
   `CombinedComponentsMatch`, `GetFieldText`, `LogTableRows`, `LogTableFields`,
   `IsDataCellType` и ветка «groups ordered by schedule table rows». Порядок
   групп снова задаёт компаратор: есть поля сортировки — сортировать; нет —
   порядок модели.
2. **Исправленный компаратор** `GroupComparer`:
   - числовые параметры (Double/Integer) — сравнение по значению;
   - текстовые значения — `NaturalStringComparer`
     (`AssemblingManager.Core.Common`, уже есть в проекте): числа внутри
     текста сравниваются как числа, текст — без учёта регистра;
   - направления (возр./убыв.) и набор полей — как в настройках спецификации.
3. **Сохраняется из v4**: значения полей читаются по `ParameterId` (не по
   имени) — исключает путаницу одноимённых параметров; влияет на группировку.
4. **Лог-диагностика**: сырые поля сортировки `GetSortGroupFields()` (имена,
   направления), порядок групп (номер → значения), позиция → значения группы.
