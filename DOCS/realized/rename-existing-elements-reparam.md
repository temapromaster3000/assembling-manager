# План: перезапись параметра у «существующих» элементов при переименовании

## Проблема

Модуль «Переименовать виды» (`RenameAssembliesCommand`) перезаписывает `AssemblyParameter` только у членов сборки (`rename.ElementIds`, строка 295). Элементы другой стадии («существующее»), добавленные модулем «Добавить существующее», в сборку не входят — у них остаётся старое имя. Новый фильтр вида «AssemblyParameter ≠ новое имя» скрывает эти элементы с вида.

## Решение

При переименовании искать во всей модели элементы, у которых `AssemblyParameter == староеИмя`, и записывать в них новое имя.

### 1. `ParameterService.cs` — новый метод

`FindElementIdsWithParameterValue(Document doc, ElementId parameterId, string value)`:

- поиск через `FilteredElementCollector` + `ElementParameterFilter` с правилом `FilterStringEqualsRule` (как в `FilterService.CreateAssemblyFilter`: R2023+ без параметра caseSensitive, R2021–2022 с `true`);
- возвращает все элементы модели со значением `value` (включая членов сборки — повторная запись того же значения безопасна).

### 2. `RenameAssembliesCommand.cs` — `ProcessRename`

После строки 295 для каждого `oldName` из `rename.OldNames`:

- найти элементы со значением `oldName`;
- перезаписать параметр на `rename.Assembly.Name` через `SetParameterValue`;
- в лог: количество обновлённых «существующих» элементов.

### Безопасность

- Элементы других сборок не затрагиваются: их параметр равен имени их сборки, а пересечения имён отсекаются проверкой «value совпадает с именем существующей сборки» (строка 97 команды).
- Члены самой переименовываемой сборки получат то же значение повторно — безвредно.

## Контрольный список ручной проверки (в Revit)

1. Добавить существующие элементы к сборке (модуль «Добавить существующее»), проверить, что они видны на видах сборки.
2. Переименовать сборку → запустить «Переименовать виды».
3. Убедиться: существующие элементы остались видимы, фильтры видов и спецификация ссылаются на новое имя.
4. Проверить, что элементы другой сборки (если есть) не затронуты.
