# Восстановление недостающих видов (окно NewViewsDialog)

## Проблема

Если проектировщик вручную удалил часть видов сборки, при повторном запуске модуля «Формирование видов» плагин молча создаёт их заново. Возникает замкнутый круг: пользователь удаляет ненужные виды (например, снятые с листов «не размещённые»), а на следующей генерации плагин возвращает их обратно.

## Цель

Перед созданием показать пользователю список «недостающих» видов — видов, которых нет в модели, но которые плагин собрался создать, — но **только для сборок, у которых уже существует хотя бы один вид из сета** (т.е. сет разрушен частично). Виды полностью новых сборок в этом окне не показываются и создаются по умолчанию, как раньше.

Пользователь сам отмечает галочками, какие виды создать. Всё снято по умолчанию — ни один недостающий вид не создастся, пока пользователь его не отметит.

## Поведение

### Окно «Недостающие виды»

Показывается после окна конфликтов (или без него, если конфликтов нет, но список недостающих видов непуст):

- заголовок: «У некоторых сборок виды созданы не полностью. Отметьте те, которые нужно создать:»;
- таблица: «Создать» (галочка) | «Тип вида» | «Сборка»;
- поиск по сборке / типу вида;
- счётчик «Выбрано: N из M»;
- кнопки «Выбрать всё / Отмена / OK».

«Отмена» возвращает пользователя в главное окно, ничего не создавая.

### Фильтрация

- Сборка попадает в список, если у неё существует хотя бы один вид из сета (план / разрезы / 3D / спецификация) и каких-то видов из набора не хватает.
- Полностью новые сборки (0 существующих видов) в окне не отображаются.
- Виды, помеченные в окне конфликтов «Заменить», считаются существующими (они будут пересозданы, а не добавлены).

### Создание

- Виды с галочкой создаются, как обычно.
- Виды без галочки пропускаются: в отчёте цифра «Пропущено видов» увеличивается, фильтры и параметры применяются как раньше.
- Если недостающих видов у сборок с неполными сетами нет — окно не показывается.

## Технические изменения

### Модели (Core)

- Новый класс `PlannedViewItem` (публичный, в `AssemblingManager.Core.Models`): `AssemblyName`, `ViewName`, `ViewTypeDisplayName`, `ViewKind`, флаг `Create` (по умолчанию `false`) с `INotifyPropertyChanged`.
- `ViewConflictResolution`: новое поле `SkipItems` (тип `List<PlannedViewItem>`) — виды, которые по выбору пользователя не создавать.

### Сервисы

- `ViewService.FindMissingViews(doc, assemblies, options)` — инверсия `FindExistingViewConflicts`: по всем сборкам и выбранным типам видов возвращает `PlannedViewItem` для каждого отсутствующего вида (без фильтра по частичности).
- `ScheduleService.FindMissingSchedules(doc, assemblies, options)` — то же для спецификаций (если создание спецификации не выбрано, список пуст).
- `OrchestratorService`:
  - `CreateOrReplaceView`: перед созданием нового вида проверяет `resolution.SkipItems` по `ViewName` + `ViewKind`; совпадение → `SkippedCount++`, вид не создаётся, результат `(null, false)`.
  - `CreateOrReplaceSchedule`: аналогично.

### Команда

`CreateAssemblyViewsCommand`:

1. Собрать `missing = FindMissingViews + FindMissingSchedules`.
2. Построить `assembliesWithExistingViews` из имён сборок, у которых есть хотя бы один существующий вид или спецификация (данные `FindExistingViewConflicts` + `FindScheduleConflicts`).
3. Отфильтровать `missing` по этому множеству.
4. Если результат непуст — показать `NewViewsDialog`; «Отмена» → `continue` (возврат в главное окно); иначе `resolution.SkipItems = missing.Where(m => !m.Create)`.

### UI

- Новый файл `Views/NewViewsDialog.xaml` + код-бихайнд — копия паттерна `ConflictDialog` (поиск, счётчик, выбор-все, сортировка по колонке, показ полной подсказки при обрезке).

## Контрольный список ручной проверки

1. Создать виды для сборки А (полный сет) и сборки Б.
2. Удалить вручную 2 вида сборки А (например, 3D и вид слева).
3. Запустить модуль «Формирование видов», выбрать те же типы видов.
4. Убедиться, что появилось окно «Недостающие виды» только с видами сборки А (без спецификации/видов сборки Б).
5. Всё снято по умолчанию; нажать OK — убедиться, что ничего не создалось (отчёт: «Пропущено видов» больше нуля, цифры правильные).
6. Повторить запуск, отметить только 3D — создать, убедиться что создан только он.
7. Проверить «Выбрать всё», поиск, сортировку по колонкам, счётчик.
8. «Отмена» в окне — возврат в главное окно без изменений.
9. Запустить модуль на полностью новой сборке (0 существующих видов) — окно не появляется, виды создаются по умолчанию.
10. Изменить состав сборки Б (удалить существующий вид), запустить — в окне только её недостающие виды.
