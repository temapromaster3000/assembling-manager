# План: спецификации по сборкам (schedule duplication)

## Статус

В процессе реализации.

## Цель

Дать пользователю возможность создавать спецификации для каждой сборки путём копирования выбранной мастер-спецификации и подмены фильтра по параметру группировки на имя конкретной сборки.

## UI

- Окно: `Height="500"`, `Width="600"`. `Grid.Margin="20"` со всех сторон — равные отступы слева, справа и снизу.
- Верхняя левая рамка «Параметр для фильтра»:
  - Радиокнопки меняются местами: сверху «Создать новый общий параметр», снизу «Использовать ADSK_Группирование».
  - По умолчанию выбран «Создать новый общий параметр».
  - Исправить опечатку `ADSK__Группирование` → `ADSK_Группирование`.
- Верхняя правая рамка «Виды для создания»:
  - Все галочки (План, Разрезы, 3D вид) по умолчанию выключены.
  - Под галочкой 3D вида добавляется `CheckBox` с текстом «Спецификация».
- Новая нижняя правая рамка «Спецификация»:
  - Высота 170, ширина равна верхней правой рамке.
  - Два выпадающих списка: «Мастер-спецификация» и «Шаблон вида» (с первым пунктом «— без шаблона —»).
  - Активна только при включённой галочке «Спецификация» (`IsEnabled` привязан к `CheckBoxSchedule.IsChecked`).
- Кнопки и счётчики «Сборок в проекте» / «Будет создано видов» переносятся в отдельную нижнюю строку, выровненную по правому краю.
- Если галочка «Спецификация» включена, но мастер-спецификация не выбрана, при нажатии «Сформировать» показывается предупреждение и диалог не закрывается.

## Модель

В `ViewCreationOptions` добавляются:

```csharp
public bool CreateSchedule { get; set; }
public int? MasterScheduleId { get; set; }
public int? ScheduleViewTemplateId { get; set; }
```

## Сервисы

### `ViewTemplateService`

- Добавить метод `GetScheduleViewTemplates(Document)` — возвращает `View`, у которых `IsTemplate && ViewType == ViewType.Schedule`.

### `ScheduleService` (новый класс)

- `ScheduleSuffix = "_Спецификация"`.
- `GetAvailableSchedules(Document)` — список `ViewSchedule`:
  - не являются шаблонами;
  - не являются ведомостями видов, листов, изменений.
- `DuplicateScheduleForAssembly(Document, ViewSchedule master, ElementId groupingParameterId, string assemblyName, int? scheduleTemplateId)`:
  1. Копировать мастер-спецификацию через `Duplicate(ViewDuplicateOption.Duplicate)`.
  2. Переименовать в `assemblyName + "_Спецификация"`.
  3. Найти поле по `ParameterId` параметра группировки. Если не найдено — добавить скрытое поле (`ScheduleFieldType.Instance`, `parameterId`), `IsHidden = true`.
  4. Найти фильтр по этому полю. Если есть — обновить его значение на `assemblyName` (Equal). Если нет — добавить фильтр `ScheduleFilterType.Equal` со значением `assemblyName`.
  5. Сохранить все остальные фильтры и форматирование мастер-спецификации.
  6. Если выбран шаблон вида — применить через `IsValidViewTemplate`; если API не позволяет, записать предупреждение в лог, но спецификацию оставить.
- `FindScheduleConflicts(Document, assemblies, options)` — находит существующие спецификации с именем `assemblyName + "_Спецификация"` для добавления в диалог замены/пропуска.

### `ViewService`

- Добавить константу `ScheduleSuffix` (или использовать `ScheduleService.ScheduleSuffix`) и включить спецификации в поиск конфликтов / существующих видов, если это требуется для диалога.

### `OrchestratorService`

- После создания видов (или в отдельном цикле) для каждой сборки создавать спецификацию, если `options.CreateSchedule == true` и выбрана мастер-спецификация.
- Использовать общий механизм замены/пропуска через `ViewConflictResolution`.
- Проверку «выберите хотя бы один вид» расширить: достаточно включённой галочки «Спецификация».

## Логика UI

- Счётчик «Будет создано видов» учитывает спецификации (по аналогии с видами).
- Если включена «Спецификация», но не выбрана мастер-спецификация — при нажатии «Сформировать» показывать предупреждение и не закрывать диалог.
- Если выбрана только «Спецификация» (без видов) — плагин создаёт только спецификации.

## Build и проверка

- Собрать конфигурации `Debug.R21` и `Debug.R25`.
- Ручной чек-лист:
  1. Окно открывается, рамки ровные, отступы одинаковые слева, справа и снизу.
  2. По умолчанию выбран «Создать новый общий параметр», все виды выключены.
  3. Рамка «Спецификация» неактивна (тусклая), пока не включена галочка.
  4. Включение галочки «Спецификация» активирует выпадающие списки в рамке.
  5. В выпадающем списке «Мастер-спецификация» нет шаблонов, ведомостей видов, листов, изменений.
  6. Создаются спецификации с именами `Сборка_01_Спецификация`.
  7. В каждой копии отображаются только строки соответствующей сборки.
  8. Повторный запуск открывает диалог замены/пропуска существующих спецификаций.
  9. Работает создание только спецификаций без видов.
  10. Если мастер-спецификация не выбрана, при нажатии «Сформировать» появляется предупреждение.

## Риски

- Применение шаблона вида к спецификации может ограничиваться API в разных версиях Revit. Обход — проверка `IsValidViewTemplate` и запись в лог; спецификация остаётся созданной.
- Если параметр группировки нельзя добавить в категорию мастер-спецификации, такая спецификация для сборки пропускается с записью в лог.
