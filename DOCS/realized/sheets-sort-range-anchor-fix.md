# Фикс: лист-«диапазон» уходит в конец при сортировке листов

## Проблема

При сортировке листов лист с названием «Трубопроводы 1.2.2.2/3.1-1.2.2.2/3.4» (на листе размещены виды нескольких сборок) получал последний порядковый номер (46), хотя по задумке должен вставать по минимальному коду диапазона — сразу после «Трубопровод 1.2.2.2» (номер 22).

## Причина (по логам `%APPDATA%\Autodesk\Revit\Addins\AssemblingManager\Logs`)

1. На листе виды нескольких сборок → `SingleBaseName == null` → якорь вырезался из имени листа по первому дефису: «Трубопровод**ы** 1.2.2.2/3.1».
2. Ключ сортировки сравнивался натурально целиком: текстовая часть «|Трубопровод**ы** » против «|Трубопровод » у всех остальных листов. Побуквенное сравнение доходило до 12-го символа: «ы» (U+044B) «больше» пробела (0x20) → лист оказывался «больше» всех листов «Трубопровод ...» → конец очереди → номер 46.
3. Правило из `docs/realized/sheets-sort-plan.md` («лист с видами нескольких сборок → минимальное имя сборки из фактических») в коде реализовано не было — `GetAnchor` умел только случай одной сборки.

## Фикс

Файл: `src/AssemblingManager.Revit/Commands/SortSheetsCommand.cs`

1. **`GetAnchor`** — добавлен шаг: если на листе распознаны виды нескольких сборок (`BaseNames.Count > 1`), якорь = минимальное имя сборки по `NaturalStringComparer`. Для проблемного листа якорем станет «Трубопровод 1.2.2.2/3.1».
2. **`BuildSortKey`** — ключ стал трёхчастным: `первые 12 цифр | код (часть якоря с первой цифры, например «1.2.2.2/3.1») | весь якорь`. Числовой код теперь главнее слова, поэтому префиксы вроде «ТрубопроводЫ», «ТК-» и т.п. не влияют на позицию. Fallback `zzzz...` для якорей без цифр не изменён.
3. **Лог** — в строку порядка сортировки добавлен сам ключ (диагностика будущих случаев).

## Регрессия первого варианта фикса (обнаружена на проверке)

Первая версия ключа использовала видимый разделитель `|` между частями. Его код символа (124) **больше** кодов `/` (47), `.` (46), `-` (45), поэтому код, который «заканчивается» (родительский, например «1.2.2.2»), сравнивался как БОЛЬШЕ кода, который «продолжается» («1.2.2.2/4.1.1»). Итог: родительские листы («Трубопровод 1.2.2.2», «1.2.3.1», «1.2.3.2») вставали после всех своих дочерних листов «.../x.y».

Исправление: внутренний разделитель ключа заменён на служебный символ `\u0001` (константа `KeyPartSeparator`) — он «меньше» любого печатного символа, поэтому «конец кода» всегда сортируется раньше «продолжения кода». В логе символ выводится как `|` для читаемости.

Проверка стенда (temp, `sortkey-harness.cs`: копия `NaturalStringComparer` + `BuildSortKey` + логика `OrderSheets`, 41 лист с реальными именами модели) — все проверки PASS:

- «Трубопровод 1.2.2.2» — сразу перед диапазоном и всеми «/4.x»;
- диапазон «ТрубопроводЫ 1.2.2.2/3.1-1.2.2.2/3.4» — сразу после «Трубопровод 1.2.2.2»;
- «1.2.3.1» и «1.2.3.2» — перед своими дочерними «/4.x», «/5.x»;
- пары «(начало)»/«(окончание)» — перед «1.2.1/1», между собой в порядке начало → окончание;
- якорь без цифр («Вентиляция») — последний;
- «3.1» перед «31.1» (натуральное сравнение не сломано).

Ожидаемый результат на тестовой модели: лист «Трубопроводы 1.2.2.2/3.1-1.2.2.2/3.4» → номер 22 (сразу после «Трубопровод 1.2.2.2»); «1.2.2.2/4.1.1»–«1.2.3.2/5.7» → 23–46; «1.2.1 (начало)»/«(окончание)» → 7–8.

## Контрольный список ручной проверки

1. Собрать и развернуть плагин (`build-and-deploy.bat`), перезапустить Revit, открыть модель.
2. Запустить «Сортировка листов», выбрать группу «05-26-01-ТК», стартовый номер 7.
3. Убедиться: «Трубопроводы 1.2.2.2/3.1-1.2.2.2/3.4» получил номер **22** и стоит сразу после «Трубопровод 1.2.2.2» (21).
4. Убедиться: листы «1.2.2.2/4.1.1»–«1.2.3.2/5.7» получили 23–46, порядок между ними прежний.
5. Убедиться: пары «(начало)»/«(окончание)» (листы 7–8) не переименованы и идут рядом.
6. Убедиться: пустые листы удалились, отчёт без неожиданных предупреждений.
7. (Опционально) Проверить в логе строку `Sheet sort order:` — якорь проблемного листа должен быть «Трубопровод 1.2.2.2/3.1».
