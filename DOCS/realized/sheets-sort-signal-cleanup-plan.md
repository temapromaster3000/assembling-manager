# Удаление сигнальных листов в модуле «Сортировка листов»

## Проблема

Модуль «Разместить на листах» создаёт сигнальные листы с припиской «(не размещенное)» — на них попадают виды сборок, которые не удалось разместить. Листы носят чисто информативный характер: пользователь смотрит и решает — он забыл разместить виды или забыл удалить их из проекта. Модуль «Сортировка листов» удаляет только пустые листы, поэтому сигнальные листы и виды на них приходится убирать вручную.

## Цель

Галочка **«Удалить сигнальные листы „(не размещенное)"»** в окне «Сортировка листов»:

- по умолчанию **снята**; между запусками не сохраняется;
- включена → в выбранной группе сигнальные листы исключаются из сортировки и перенумерации и удаляются **вместе с содержимым**:
  - виды сборок (планы/разрезы/3D) и сборочные спецификации-дубликаты («..._Спецификация») удаляются из проекта полностью;
  - удаляются только **плагиновые** элементы (базовое имя вида/спецификации соответствует имени сборки в модели); посторонние виды, добавленные на сигнальный лист вручную, остаются в проекте неразмещёнными — в отчёт уходит предупреждение;
- отчёт дополняется строками «Удалено сигнальных листов: N» и «Удалено видов и спецификаций с сигнальных листов: M»;
- удалённые виды пересоздаются кнопкой «Сформировать виды» — другие модули (переименование, марки, фильтры) работают по факту наличия видов и не ломаются.

## Регрессия при тестировании в файле-хранилище (исправляется)

HTML-отчёт Revit + лог выявили: транзакции коммитились, но Revit на этапе фиксации **откатывал удаления и перенумерацию** элементов, чьи рабочие наборы принадлежали другим пользователям («Операция вызвала удаление нередактируемого рабочего набора», «У вас нет разрешения редактировать этот элемент», «Невозможно изменить рабочий набор»). Команда при этом отчитывалась успехом с завышенными счётчиками (три прогона подряд «удаляли» одни и те же 12 листов); наш `FailurePreprocessor` глотал ошибки без логирования.

Исправления (worksharing-устойчивость):

1. **Новый `Services/WorksharingService.cs`**: `CheckEditable(doc, ids)` — пытается захватить элементы (`WorksharingUtils.CheckoutElements`, документированный паттерн Autodesk), возвращает успешно захваченные + список пропущенных с владельцем (`WorksharingUtils.GetWorksharingTooltipInfo`) и причиной (`GetModelUpdatesStatus`: удалено/изменено в центральной модели). Для не-workshared моделей — всё редактируемо.
2. **Единая проверка перед записями** (`SortSheetsCommand`): пустые листы, сигнальные листы с содержимым (группами «лист + его виды/спецификации» — если хоть один элемент занят, лист целиком пропускается), переименование и перенумерация.
3. **Верификация после удаления**: счётчики в отчёте — фактические (проверка `doc.GetElement` после `Delete`); выжившие элементы — отдельным предупреждением.
4. **Защита от дублей номеров**: номера пропущенных листов учитываются как занятые при перенумерации (`RenumberSheets`); занятые листы пропускаются без записи временных/окончательных номеров.
5. **`FailurePreprocessor`**: каждый сбой Revit логируется (тип, текст, элементы) до `DeleteWarning`.
6. **Компактный отчёт**: пер-листовые предупреждения убраны (детали — в лог); в отчёте — агрегаты: «Не удалены (заняты другими пользователями): …», «Не переименовано/перенумеровано (занято): N листов», «Владельцы занятых элементов: …», «Посторонние виды и спецификации, сохранённые в проекте: N».
7. Финальная строка лога команды включает сигнальные счётчики.

## Доработки после тестов в файле-хранилище

1. **«Посторонние» элементы = графа ревизий штампа.** На каждом сигнальном листе ровно один «посторонний» элемент — `ScheduleSheetInstance` графы изменений ревизии, встроенной в штамп (её служебная спецификация не имеет имени вида «ИмяСборки_Спецификация»). Исправление: `CollectSignalSheetContent` пропускает экземпляры с `IsTitleblockRevisionSchedule == true` — они не содержимое листа, отдельно не удаляются (уходят вместе со штампом) и в счётчик не попадают.
2. **Занятые номера листов** — вместо «Номер «N» занят за пределами группы — использован следующий свободный»: одна строка `Занятые номера листов: №21 — Трубопровод 1.2.2.2 (e.polomar), №36 — … (d.klemantovich).` (только номера, реально помешавшие нумерации; для листов вне группы владелец запрашивается точечно).
3. **Статус целостности нумерации**: для каждого занятого листа сравнивается его сохранённый номер с позицией в новом порядке; в отчёт выводится `Нумерация не сбилась (занятые листы сохранили номера, соответствующие порядку)` либо `Нумерация сбилась: «имя» — номер X вместо Y (владелец: …). Освободите занятые листы/виды и повторите модуль.`

## Реализация

1. **`SheetService.cs`** — общая константа `SignalSheetSuffix = " (не размещенное)"` (раньше суффикс дублировался строками в двух командах, с пробелом и без) и статический хелпер `IsSignalSheetName(string)`.
2. **`PlaceViewsOnSheetsCommand.cs`** — локальная константа удалена, используется `SheetService.SignalSheetSuffix`.
3. **`SheetsSortDialog.xaml/.cs`** — новый ряд с чекбоксом `DeleteSignalSheetsCheckBox` (IsChecked=False) и свойство `DeleteSignalSheets`.
4. **`SortSheetsCommand.cs`**:
   - `SheetAnalysis.IsSignal` заполняется в `BuildAnalysis` через `IsSignalSheetName`;
   - при включённой галочке сигнальные листы (не пустые) исключаются из очереди сортировки/перенумерации;
   - до транзакции: `CollectSignalSheetContent` собирает ID плагиновых видов и спецификаций с каждого сигнального листа (фильтр через `IsAssemblyBaseName`/суффикс `_Спецификация`), чужой контент фиксируется предупреждением;
   - в транзакции: один `document.Delete(...)` для пустых листов + сигнальных листов + собранных видов/спецификаций (Revit сам разруливает зависимости лист↔вьюпорт↔вид);
   - `SheetsSortResult`: новые счётчики `SignalSheetsDeletedCount`, `SignalViewsDeletedCount`;
   - `ManualSheetSuffixes` использует общую константу.
5. **`SheetsSortReportDialog.xaml.cs`** — конструктор расширен двумя счётчиками, новые строки статистики.

## Контрольный список ручной проверки

1. Запустить «Сортировку листов»: галочка по умолчанию снята — поведение прежнее (сигнальные листы сортируются и перенумеровываются).
2. Создать условия: у какой-то сборки часть видов размещена, часть нет → есть сигнальный лист «(не размещенное)».
3. Включить галочку, выполнить: сигнальные листы удалены; виды и сборочные спецификации с них исчезли из проекта (проверить диспетчер видов).
4. Остальные листы перенумерованы без пропусков номеров; имена листов не тронуты.
5. В отчёте: «Удалено сигнальных листов: N», «Удалено видов и спецификаций: M»; при наличии вручную добавленного вида на сигнальном листе — агрегированная строка «Посторонние виды и спецификации, сохранённые в проекте: P».
6. Сценарий файл-хранилища: проектировщик держит занятыми часть листов/видов → плагин завершается успешно; в отчёте — «Не удалены / Не переименовано/перенумеровано (заняты другими пользователями)», «Владельцы занятых элементов: …», «Занятые номера листов: №N — имя (владелец)…» и строка статуса «Нумерация не сбилась…» / «Нумерация сбилась: …»; занятые листы не тронуты, дубли номеров не появились; детали (элемент + владелец) — в логе.
7. «Сформировать виды» после чистки пересоздаёт виды для тех же сборок без конфликтов.
8. Если сигнальных листов в группе нет — команда отрабатывает как обычно, отчёт без сигнальных строк.
9. «Отмена» в окне — модель не меняется.
