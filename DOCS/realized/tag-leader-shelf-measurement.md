# План: правильное примыкание выносок марок на любых видах

## Проблема

В модуле «Проставить позиции» на пользовательском разрезе многие выноски марок встали
«по центру полки». Причина: замер габаритов марки (пробной маркой) привязан к паре
«типоразмер + вид»; если первый элемент категории невидим в виде (узкая обрезка
пользовательского разреза), замер срывается (`MeasureTagDimensions` молча выходит при
`anchor == null`, TagService.cs:1144-1148), кэш пуст, и в fallback (строки 755-757) излом
ставится в `TagHeadPosition` = начало координат семейства. У семейств с утопленным
началом координат это визуально «центр полки». На разрезах плагина замер всегда успешен
(обрезка покрывает всю сборку), поэтому проблема проявляется только на пользовательских
разрезах.

## Решения (согласованы с пользователем)

1. **Замер — один на типоразмер, не на вид.** Габариты графики марки зависят только от
   типоразмера, текста и масштаба — от вида не зависят.
2. **Пересчёт по масштабу**: графика марки растёт линейно с масштабом вида, зазоры
   масштабируются пропорцией `зазор × (масштаб_вида / масштаб_замера)`.
3. **Страховка**: если замер так и не удался, у первой реальной марки измерить её
   фактический bbox (временно собрав все точки выноски в голову), занести в кэш и
   поставить излом у вычисленного края полки.

## Изменения (`TagService.cs`)

### 1. Замер — многокандидатный, ключ кэша по типоразмеру
- `PrepareTagDimensions`: для каждого типоразмера собирается до 10 кандидатов (вид,
  элемент) — элементы плана сборки приоритетны (план идёт первым в списке видов), затем
  другие виды.
- `MeasureTagDimensions`: ключ кэша = Id типоразмера (без вида); хранится масштаб замера
  (`TagDims.MeasuredScale`); замер по кандидатам по очереди до первого успеха.
- Если кандидаты исчерпаны без успеха — предупреждение в лог (сейчас — тишина).

### 2. Пересчёт по масштабу
- `GetTagDimensions(view, symbol)`: если измерено при другом масштабе — все зазоры и
  габариты умножаются на `масштаб_вида / масштаб_замера`.

### 3. Страховка в `PlaceTagsInView` (ветка `!dimsKnown`)
- После создания реальной марки: временно собрать `LeaderEnd`, `LeaderElbow` и голову в
  одну точку (как у пробника), вызвать `doc.Regenerate()`, прочитать фактический bbox
  марки в виде, вычислить реальные зазоры, занести в кэш (с масштабом этого вида),
  восстановить конец выноски на элемент и поставить излом у края полки.
- Последующие марки типоразмера работают уже по кэшу (`dimsKnown = true`).

### Не меняется
- Алгоритм «лесенки» (4 диагонали, зоны, stepFt), порядок операций в команде,
  поведение на разрезах плагина (замер там успешен — результаты те же).

## Контрольный список ручной проверки (в Revit)

1. «Проставить позиции» на пользовательском разрезе → выноски примыкают к краям полок
   (левее/правее), не по центру.
2. Пользовательский разрез с масштабом, отличным от плана (например, 1:25 при плане 1:50)
   → примыкание корректно (проверка пересчёта по масштабу).
3. Разрезы плагина → без регрессий.
4. Сборка без плана (только разрезы) → замер по видимому элементу разреза; если видимых
   нет — страховка (излом по фактическому bbox).
