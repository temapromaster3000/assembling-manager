# План: улучшение окна конфликтов (ConflictDialog)

## Цель
Сделать окно «Найдены существующие виды» удобнее и привести его к стилю главного окна.

## Изменения

### 0. Общие стили — вынос в общий файл
- Создан `src/AssemblingManager.Revit/Styles/Common.xaml` (ResourceDictionary).
- Стиль `PrimaryButton` перенесён из `MainWindow.xaml` без изменений.
- Словарь подключён в `MainWindow.xaml` и `ConflictDialog.xaml`.
- Причина: у плагина нет `App.xaml`, стили из ресурсов одного окна не видны другим окнам.

### 1. Кнопка «OK» — стиль PrimaryButton
- Синяя скруглённая кнопка, как «Сформировать» в главном окне.

### 2. Счётчик выбранных
- Строка «Выбрано: N из M» слева от кнопок.
- Обновляется при загрузке, при клике на чекбокс, при «Выбрать всё».

### 3. Размеры окна и колонки таблицы
- Главное окно вернули к авто-высоте (`SizeToContent="Height"`, ширина 620) — кнопки и отступы гарантированно не ломаются. Опыт с явной высотой 470 показал: точную естественную высоту окна не вычислить заранее (зависит от шрифтов и оформления Windows), при несовпадении режутся нижние кнопки.
- Окно конфликтов зафиксировано явно: **620×485** (близко к фактической высоте главного окна; лишние пиксели у диалога уходят в список видов, поэтому его вёрстка не ломается при любой высоте).
- Колонки: Заменить — жёстко 70 px → Тип вида — жёстко 120 px → Сборка — жёстко **388 px** (620 − поля 40 − рамка 2 − 190).
- Формула «x / x − y»: при первом показе окна (`ContentRendered`) код находит внутренний прокрутчик списка и подписывается на его изменения; пока вертикального ползунка нет — колонка 388 px, появился ползунок — видимая область сужается, ширина колонки пересчитывается (≈371 px), исчез — снова 388 px.
- Горизонтальный ползунок отключён полностью (`ScrollViewer.HorizontalScrollBarVisibility="Disabled"`).
- Вертикальный ползунок работает как раньше: строк больше, чем влезает по высоте → появляется справа.

### 4. Длинные имена сборок
- Текст в ячейке «Сборка» обрезается с троеточием (`TextTrimming="CharacterEllipsis"`).
- Подсказка с полным именем всплывает **только если имя не влезло**: в обработчике `ToolTipOpening` измеряется текст; если он виден целиком — подсказка отменяется (`e.Handled = true`).

### 5. Чередование строк
- `AlternationCount="2"`, нечётные строки подсвечены `#F5F7F8`.

### 6. Клик по строке переключает чекбокс
- Обработчик `PreviewMouseLeftButtonUp` на строке списка.
- Клик по самому чекбоксу игнорируется (чтобы не было двойного переключения).

### 7. Двусторонняя сортировка по колонкам
- Клик по заголовку «Сборка» / «Тип вида» сортирует список; повторный клик по той же колонке переворачивает направление (А→Я ↔ Я→А).
- В заголовке активной колонки отображается стрелка: «▲» — по возрастанию, «▼» — по убыванию; при переключении на другую колонку стрелка переносится.
- Технически: присоединённое событие `GridViewColumnHeader.Click` на `ListView` + `SortDescriptions`; код помнит активную колонку и направление, стрелка отрезается от текста заголовка перед разбором клика.

### 8. Мгновенное обновление галочек (исправление бага)
- Было: при клике по строке галочка меняла значение в данных, но на экране не перерисовывалась до сортировки/обновления списка.
- Причина: модель `ViewConflictItem` не уведомляла интерфейс об изменениях.
- Стало: модель реализует `INotifyPropertyChanged`, свойство `Replace` рассылает `PropertyChanged`.
- Костыль `Items.Refresh()` из кнопки «Выбрать всё» удалён — больше не нужен.

### 9. Запрет ручного изменения колонок
- Свой шаблон заголовков `GridViewColumnHeader` без встроенного «захвата» ширины — перетаскивать границу колонки нельзя.
- `AllowsColumnReorder="False"` — нельзя менять колонки местами перетаскиванием заголовка.
- Заголовки оформлены в стиле окна: жирный текст, разделители цветом рамок `#FFD5DFE5`. Сортировка кликом сохранена.

### 10. Центрирование заголовков и галочек
- Текст заголовков выровнен по центру своей колонки (`HorizontalAlignment="Center"` в шаблоне), разделители остаются на всю ширину.
- Чекбокс в колонке «Заменить» обёрнут в `Grid` с явной шириной 58 (колонка 70 минус стандартные внутренние отступы ячейки по 6 px с каждой стороны). Причина: контейнер ячейки GridView не растягивает содержимое на всю ячейку, а укладывает его слева «по содержимому» — без явной ширины центрирование не работает.

### 11. Скрытие служебного заполнителя справа от таблицы (исправление падения)
- Было: клик по пустой области справа от последней колонки вызывал `NullReferenceException` и падение плагина — там служебный заголовок без колонки, а обработчик сортировки читал его «колонку» без проверки.
- Стало: после полной раскладки списка (отложенно, через `Dispatcher.BeginInvoke` с приоритетом `Loaded`) заполнитель находится в визуальном дереве и скрывается (`Visibility="Collapsed"`) — таблица заканчивается сразу после «Сборки». То же повторяется при изменении размеров списка (`SizeChanged`).
- Ширина «Сборки» считается без запаса: ровно видимая область минус две первые колонки; при крошечном переполнении горизонтальная прокрутка отключена, лишнее невидимо обрезается.
- Страховка: в обработчике сортировки добавлена проверка `header.Column == null` — просто выход.

### 12. Выделение строк и массовая установка галочек (двухфазная модель)
- Клик по строке (любой части, кроме квадратика) — только выделение, галочка не переключается. Режим `SelectionMode="Extended"`: обычный клик — одна строка, Shift+клик — диапазон, Ctrl+клик — отдельные строки; выделенные строки подсвечиваются синим.
- Клик по квадратику строки, входящей в выделение из нескольких строк, — новое состояние применяется ко **всем выделенным** строкам: поставили галочку — все выделенные отмечены, сняли — все снялись.
- Клик по квадратику строки вне выделения (или при единственном выделении) — работает как обычно, только своя строка.
- Технически: у чекбокса используется событие `Click` (срабатывает только от реального клика), программные обновления галочек через привязку не вызывают цепных срабатываний; счётчик «Выбрано: N из M» обновляется после клика.

### 13. Поиск по конфликтам
- Между инструкцией и таблицей добавлено поле поиска с серой подсказкой «Поиск по сборке или типу вида…» (исчезает при вводе).
- Фильтрация на лету при каждом введённом символе, без учёта регистра, по подстроке: строка остаётся, если текст найден в «Сборке» или «Типе вида». Пустой поиск — показываются все строки.
- Кнопка «✕» внутри поля очищает поиск (видна только при непустом тексте); клавиша Esc тоже очищает.
- Технически: штатная фильтрация WPF (`ICollectionView.Filter`) — сортировка со стрелками работает поверх фильтра, счётчик «Выбрано: N из M» считает по всем конфликтам, массовая установка галочек по выделению не изменилась.

## Найденные нюансы API
- У WPF `GridView` нет события `ColumnHeaderClick` (это из UWP/WinUI). В WPF используется присоединённое событие `GridViewColumnHeader.Click`, подписывать нужно на `ListView`.
- Относительный путь в `ResourceDictionary Source` считается **от папки XAML-файла**, где он написан: из `Views/MainWindow.xaml` путь `Styles/Common.xaml` искался как `Views/Styles/Common.xaml` и падал с `IOException` при открытии окна. Правильный способ — явный путь с указанием сборки: `Source="/AssemblingManager;component/Styles/Common.xaml"`.
- У `ListView` нет прямого свойства `HorizontalScrollBarVisibility` — это присоединённое свойство `ScrollViewer.HorizontalScrollBarVisibility`.
- Горизонтальный ползунок у `GridView` появляется только когда **сумма ширин колонок** больше ширины списка; переполнение текста внутри фиксированной колонки ползунок не включает. Поэтому длинные имена обрезаются троеточием с подсказкой.
- Изменить ширину колонки пользователем можно только через «грип» в стандартном шаблоне заголовка; свой шаблон без `PART_HeaderGripper` запрещает изменение ширины.
- Контейнер ячейки GridView не растягивается на всю ширину ячейки — центрирование содержимого работает только внутри растягиваемого контейнера (например, `Grid`).
- Область справа от последней колонки таблицы — служебный заголовок-заполнитель `GridViewColumnHeader` c `Column == null`; обращение к его «колонке» вызывает `NullReferenceException`.

## Контрольный список ручной проверки (в Revit)
1. Собрать и развернуть плагин через `build-and-deploy.bat`.
2. Главное окно открывается без ошибок, кнопка «Сформировать» синяя.
3. Создать ситуацию с конфликтом: запустить формирование видов второй раз для той же сборки.
4. В окне конфликтов проверить:
   - [ ] Главное окно выглядит как раньше: кнопки «Отмена»/«Сформировать» целые, снизу под ними такой же отступ, как по бокам.
   - [ ] Окно конфликтов фиксированного размера 620×485, визуально совпадает с главным окном.
   - [ ] Кнопка «OK» синяя, со скруглением; при наведении темнеет.
   - [ ] Внизу слева виден счётчик «Выбрано: N из M»; при кликах по чекбоксам он меняется.
   - [ ] Строки списка чередуются белым и светло-серым.
   - [ ] Клик по строке (кроме квадратика) только выделяет её, галочка не переключается.
   - [ ] Shift+клик выделяет диапазон строк, Ctrl+клик добавляет отдельные строки, выделенные подсвечены.
   - [ ] Клик по квадратику выделенной строки применяет её новое состояние ко всем выделенным строкам (поставили — все отмечены, сняли — все сняты).
   - [ ] Клик по квадратику невыделенной строки переключает только её.
   - [ ] Клик по заголовкам «Сборка», «Тип вида» сортирует список; повторный клик по той же колонке переворачивает направление.
   - [ ] У активной колонки видна стрелка «▲»/«▼»; при переключении на другую колонку стрелка переносится.
   - [ ] Поиск фильтрует список на лету, без учёта регистра, по «Сборке» и «Типу вида»; пустой поиск показывает все строки.
   - [ ] Кнопка «✕» и клавиша Esc очищают поиск; при активном фильтре сортировка продолжает работать.
   - [ ] Колонки: «Заменить», «Тип вида», затем «Сборка» — при коротких именах «Сборка» всё равно доходит до правого края; при появлении вертикального ползунка ширина колонки подстраивается без щелей.
   - [ ] Пытаться потянуть границу заголовка и перетащить заголовок — ничего не должно двигаться.
   - [ ] Заголовки колонок выровнены по центру своих колонок.
   - [ ] Галочки стоят ровно по центру колонки «Заменить».
   - [ ] Пустой области справа от колонки «Сборка» нет; клик у правого края таблицы не вызывает ошибку.
   - [ ] Длинное имя сборки обрезается с «…»; при наведении на такую строку всплывает полное имя; короткие имена подсказку не показывают.
   - [ ] Горизонтального ползунка нет вообще; при большом числе строк появляется вертикальный.
   - [ ] «Выбрать всё» / «Снять всё» работает, счётчик обновляется, галочки перерисовываются сразу.
