# Раскладка окна: две рамки, счётчики и кнопки внизу

## Статус

Implemented.

## Цель

Перекомпоновать `MainWindow` так, чтобы выбор параметра и видов располагались в одном ряду, а счётчики и кнопки — внизу окна.

## Поведение

- Окно шириной 600 и высотой 400.
- В верхней части две рамки рядом:
  - **слева**: «Параметр для фильтра» (Height=150);
  - **справа**: «Виды для создания» (Height=150).
- В рамку «Виды для создания» переносятся:
  - `CheckBoxPlan` — «План»;
  - `CheckBoxSections` + стрелка + `Popup` — «Разрезы»;
  - `CheckBox3D` — «3D вид».
- Отдельная надпись «Выберите виды для создания:» убирается.
- В рамке «Параметр для фильтра» радиокнопки имеют `HorizontalAlignment="Left"`, чтобы кликабельная область не растягивалась за пределы текста.
- В рамке «Виды для создания» чекбоксы имеют `HorizontalAlignment="Left"` для той же цели, а их верхние отступы убраны, чтобы первый чекбокс был на одной высоте с первой радиокнопкой слева.
- `Popup` разрезов открывается/закрывается по стрелке через `PreviewMouseDown` + `Click`. `PlacementTarget` задаётся в коде после `InitializeComponent`, а не через `Binding ElementName` в XAML, чтобы избежать ошибки BAML при загрузке окна.
- Стрелка у разрезов заменена на иконку-шеврон `\u0026#xE011;` из шрифта **Segoe MDL2 Assets**, смотрящую вниз.
- При выборе `ADSK_Группирование` обе строки статуса всегда оранжевые, даже при значении 0.
- Если параметр `ADSK_Группирование` не найден или привязан к типам (`TypeBinding`), кнопка «Сформировать» остаётся активной, но при нажатии выводится `MessageBox` с подробным объяснением:
  - «Параметр ADSK_Группирование не создан в данном проекте».
  - «Параметр ADSK_Группирование создан для типов, плагин должен записывать значения в экземпляры».
- Счётчики в нижней части разбиты на единый `Grid` с тремя колонками: надпись (выравнивание вправо), отступ 10 px, значение (выравнивание влево). Числа располагаются друг под другом.

## Изменения в коде

### 1. `MainWindow.xaml`

- `Width="600"`, `Height="400"`.
- Основной `Grid` разделён на 4 строки: Auto, *, Auto, Auto.
- Первая строка — вложенный `Grid` с двумя колонками для рамок параметра и видов.
- Рамка «Виды для создания» содержит `StackPanel` с чекбоксами видами и `Popup`.
- В рамке «Параметр для фильтра» радиокнопки и в рамке «Виды для создания» чекбоксы имеют `HorizontalAlignment="Left"`.
- В рамке «Виды для создания» у первого чекбокса убран верхний отступ, у следующих — отступ 5 px, чтобы выровнять их по высоте с радиокнопками слева.
- Для кнопки-стрелки добавлен `PreviewMouseDown` для корректного закрытия/открытия `Popup`.
- `PlacementTarget` у `Popup` задаётся в `MainWindow` после `InitializeComponent`, чтобы не зависеть от XAML-привязки.
- Треугольник у разрезов заменён на иконку-шеврон `\u0026#xE011;` из шрифта **Segoe MDL2 Assets** (стандартный Windows-шрифт иконок). Кнопка-шеврон 16×16, выровнена по центру строки «Разрезы».
- Счётчики внизу разбиты на единый `Grid` с тремя колонками: надпись (выравнивание вправо), отступ 10 px, значение (выравнивание влево).
- Вторая строка — растягивающееся пустое пространство.
- Третья строка — счётчики, выровнены вправо.
- Четвёртая строка — кнопки, выровнены вправо.
- Кнопка «Сформировать» имеет `Background="Blue"` и `Foreground="White"`.

### 2. `MainWindow.xaml.cs`

- Добавлено поле `_wasPopupOpen` и обработчик `ButtonSectionOptions_PreviewMouseDown` для запоминания состояния `Popup` до его автоматического закрытия.
- `ButtonSectionOptions_Click` использует `_wasPopupOpen`, чтобы повторный клик закрывал `Popup`, а не открывал снова.
- В `ValidateGroupingParameter` добавлены флаги `_groupingParameterMissing` и `_groupingParameterTypeBinding`. Кнопка «Сформировать» больше не блокируется при невалидном параметре; вместо этого флаги используются в `ButtonCreate_Click` для показа `MessageBox` с подробным сообщением.
- В `ButtonCreate_Click` добавлены проверки флагов параметра перед созданием `ViewCreationOptions` и заполняется `MissingCategoriesCount`.
- В `UpdateCounter` обновляются только числовые значения счётчиков.

### 3. `ViewCreationOptions`

- Добавлено свойство `MissingCategoriesCount` для передачи количества недостающих категорий из UI в `OrchestratorService`.

### 4. `OrchestratorService.cs`

- `AddMissingCategories` вызывается только при `options.UseExistingGroupingParameter && options.MissingCategoriesCount > 0`. Это устраняет задержку при формировании видов, когда категории уже привязаны.
