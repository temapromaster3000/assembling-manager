# Применение шаблонов видов к создаваемым видам сборок

## Статус

`in-progress`

## Цель

Дать пользователю возможность выбрать шаблоны видов в главном окне плагина и автоматически применить их к создаваемым/заменяемым видам:
- планам этажей;
- четырём видам спереди/сзади/справа/слева (сечениям);
- 3D-видам.

## Принятые решения

- **Один шаблон на все 4 вида сбоку.** Виды спереди/сзади/справа/слева создаются как `ViewSection` (`ViewFamily.Section`), поэтому для них выбирается один шаблон сечений.
- **Не применять шаблон к пропущенным существующим видам.** Если пользователь выбирает «Пропустить», старый вид остаётся без изменений.
- **Выбор шаблонов не сохраняется между запусками.** При каждом открытии окна выбирается заново, первый пункт — «— без шаблона —».
- **Только совместимые шаблоны.** В каждом выпадающем списке отображаются шаблоны соответствующего семейства: планы (`FloorPlan`), боковые виды (`Section`, `Elevation`, `Detail` — то, что Revit группирует в одной категории «Фасады, разрезы, выносные элементы») и 3D-виды (`ThreeD`). Неподходящие шаблоны отсеиваются при создании вида через `IsValidViewTemplate`.
- **UI остаётся компактным.** Высота окна `420 px`, рамка «Шаблоны видов» высотой `170` размещается снизу слева, счётчик и кнопки — снизу справа, выровнены по нижней границе рамки.

## Архитектурные изменения

### 1. `ViewCreationOptions` (Core)

Добавить три nullable-свойства для хранения ID выбранных шаблонов:

```csharp
public int? PlanTemplateId { get; set; }
public int? SectionTemplateId { get; set; }
public int? View3DTemplateId { get; set; }
```

`ElementId` не используется, чтобы не тащить зависимость от Revit API в `Core`.

### 2. `ViewTemplateService` (Revit.Services)

Новый сервис:
- собирает `View`, у которых `IsTemplate == true`;
- фильтрует по `ViewType`;
- возвращает `List<ViewTemplateItem>` с первым элементом «— без шаблона —» (`Id = null`).

```csharp
public class ViewTemplateItem
{
    public string Name { get; set; }
    public int? Id { get; set; }
}
```

Методы:
- `GetPlanTemplates(Document)` — `ViewType.FloorPlan`;
- `GetSectionTemplates(Document)` — `ViewType.Section`, `ViewType.Elevation`, `ViewType.Detail` (всё, что Revit показывает в группе «Фасады, разрезы, выносные элементы»);
- `GetView3DTemplates(Document)` — `ViewType.ThreeD`;
- `IsTemplateLockingFilters(Document, int templateId)` — проверяет, контролирует ли шаблон параметр `VIS_GRAPHICS_FILTERS` (фильтры видимости/графики). Параметр считается контролируемым, если он присутствует в `GetTemplateParameterIds()` и **отсутствует** в `GetNonControlledTemplateParameterIds()` (то есть включён галочкой «Включить»).

### 3. `ViewService` (Revit.Services)

Добавить метод:

```csharp
public void ApplyViewTemplate(View view, int? templateId)
```

- Если `templateId` отсутствует — ничего не делает.
- Если шаблон не валиден для вида (`view.IsValidViewTemplate(id) == false`) — пропускает и пишет предупреждение в лог.
- Иначе устанавливает `view.ViewTemplateId = id`.

### 4. `MainWindow` (Revit.Views)

#### XAML

- Окно `Height="420"`, `Width="600"`, `ResizeMode="NoResize"`.
- Строки главного `Grid` сокращаются до двух:
  - строка 0 — фильтр и виды;
  - строка 1 — шаблоны + счётчик/кнопки.
- Отступ между верхними рамками и нижней рамкой — `10` (как между левой и правой верхними рамками).
- В строке 1 добавляется внутренний `Grid` с двумя колонками:
  - слева `GroupBox` «Шаблоны видов» высотой `170` с тремя `ComboBox` (План, Разрезы, 3D вид);
  - справа `StackPanel`, прижатый к низу-правому краю, содержащий текущий счётчик и кнопки без изменений.

#### Code-behind

- В конструкторе создаётся `ViewTemplateService`.
- При открытии окна загружаются шаблоны и заполняются `ComboBox`.
- При нажатии «Сформировать»:
  - собираются выбранные шаблоны и типы видов, которые будут созданы;
  - для каждого выбранного шаблона проверяется, блокирует ли он фильтры;
  - если **все** выбранные шаблоны блокируют фильтры — показывается `MessageBox` с кнопкой **OK**, окно не закрывается, пользователь должен выбрать другие шаблоны;
  - если блокирует **часть** шаблонов — показывается `MessageBox` с кнопками **Да / Нет** и списком типов видов, которые не будут созданы; при согласии соответствующие флаги в `ViewCreationOptions` сбрасываются в `false`;
  - при отказе окно остаётся открытым для исправления выбора.

### 5. `OrchestratorService` (Revit.Services)

- Метод `CreateOrReplaceView` получает дополнительный параметр `int? templateId`.
- После создания/замены вида вызывается `_viewService.ApplyViewTemplate(createdView, templateId)`.
- Для каждого типа вида передаётся соответствующий `Id` из `ViewCreationOptions`:
  - план — `PlanTemplateId`;
  - виды спереди/сзади/справа/слева — `SectionTemplateId`;
  - 3D — `View3DTemplateId`.

### 6. Логирование

- В лог пишется, какие шаблоны выбрал пользователь.
- В лог пишется, если шаблон не удалось применить (несовместимость или шаблон удалён).
- В лог пишется, если фильтр не удалось применить к виду (например, шаблон блокирует фильтры и проверка это не отловила).

## Ручная проверка

### Подготовка
- Создать в тестовом проекте 2–5 сборок.
- Создать в проекте шаблоны видов:
  - шаблон плана (`FloorPlan`);
  - шаблон разреза (`Section`);
  - шаблон 3D-вида (`ThreeD`).

### Проверка UI
- Открыть плагин, убедиться, что в рамке «Шаблоны видов» три выпадающих списка.
- В каждом списке первый пункт — «— без шаблона —».
- В списке «План» только плановые шаблоны, в «Разрезы» шаблоны сечений, фасадов и узлов (`Section`, `Elevation`, `Detail`), в «3D вид» только 3D-шаблоны.
- Если шаблонов какого-то типа нет, список содержит только пункт «— без шаблона —».

### Проверка создания видов
- Выбрать шаблоны для всех трёх групп, создать виды.
- Проверить, что у созданных видов в свойствах Revit установлены выбранные шаблоны.
- Повторный запуск с заменой — у новых видов шаблоны применяются.
- Повторный запуск с пропуском — у старых видов шаблоны не меняются.
- Если выбран «— без шаблона —», вид создаётся без шаблона.
- Создать шаблоны, которые контролируют фильтры (заблокированы V/G Overrides Filters):
  - если такой шаблон выбран у всех типов видов — должно появиться сообщение «Все выбранные шаблоны блокируют...» и окно не должно закрываться;
  - если такой шаблон выбран только у части типов — должно появиться сообщение с предложением пропустить эти виды; при согласии они не создаются, остальные создаются корректно.

### Проверка сборки
- Сборка `Debug.R21` и `Debug.R25` проходит без ошибок и предупреждений.

## Риски

- Виды спереди/сзади/справа/слева создаются как сечения. Если пользователь ожидает применить шаблон фасада (`Elevation`), это потребует отдельной доработки логики создания видов.
- Применение шаблона происходит внутри транзакции. Если шаблон будет удалён между выбором в UI и созданием вида, метод `ApplyViewTemplate` пропустит его и запишет предупреждение.
- Проверка «блокирует ли шаблон фильтры» основана на внутреннем параметре `VIS_GRAPHICS_FILTERS`. Если на какой-то версии Revit этот параметр не будет доступен через `BuiltInParameter`, проверка не сработает, но в лог запишется предупреждение при неудаче применения фильтра (защита в `FilterService.ApplyFilterToView`).
