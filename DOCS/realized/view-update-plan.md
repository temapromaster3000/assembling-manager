# Обновление видов вместо пересоздания при конфликте

## Проблема

При добавлении новых элементов в сборку главный модуль предлагает либо «Заменить» (пересоздание вида — пропадают аннотации и оформление), либо «Оставить» (вид не меняется — новые элементы остаются за границами crop/разрезбокса и невидимы).

## Решение

Новое действие «Обновить» в окне конфликтов: вид остаётся тем же элементом (аннотации, теги, оформление живы), плагин только расширяет его границы до union «текущая граница + новый габарит сборки (с отступом 500 мм)». Существующие границы не сужаются — ручная подгонка проектировщика сохраняется.

### Принятые решения

- Границы — только расширять (union), не пересчитывать заново.
- UI — колонка-комбобокс «Действие»: Оставить как есть / Обновить / Заменить (вместо галочки «Заменить»).
- Спецификации включены в «Обновить»: перепроверка фильтра по имени сборки без пересоздания (`ScheduleService.UpdateScheduleFilter`).
- 3D: разблокировать → расширить `SetSectionBox` union со старым разрезбоксом → снова запереть (ориентация сохраняется).
- Блокировка активного вида остаётся только для «Заменить»; «Обновить» активный вид разрешён. Предварительная проверка (до окна) убирается — действует только пост-проверка по выбранным действиям.
- Гарантированная привязка недостающих категорий параметра в обеих ветках (существующий ADSK_Группирование и плагиновый AssemblyParameter) — иначе новые элементы новой категории не получат значение параметра.

### Механика по типам видов

- **План**: CropBox расширяется в локальных координатах текущего transform (сохраняет поворот), Z по правилам создания (округление до сотен мм ± 500 мм); плоскости View Range (верх/низ/глубина) расширяются только наружу; режущая плоскость сдвигается, только если оказалась за пределами нового диапазона; уровни View Range не меняются (если пользователь сменил уровни — диапазон не трогаем, лог Debug).
- **Разрезы**: направление берём из текущей CropBox-матрицы, новый габарит переводим в её локальные координаты, границы = union (+ минимальный размер 10 мм).
- **3D**: union старого и нового разрезбоксов по осям (мировые координаты).
- Все методы обновления — try/catch с Warn: занятый чужой вид в файл-хранилище не обновится, но прогон не откатится (в отличие от замены).

## Контрольный список ручной проверки

1. Добавлен элемент в сборку → «Обновить» для её видов → элемент виден на плане/разрезах/3D, аннотации и оформление на месте.
2. Повторное «Обновить» без новых элементов → лог Info, границы не изменились.
3. Спецификация «Обновить» → не пересоздана, поля/форматирование сохранены, новый элемент в ней есть.
4. «Заменить» работает как раньше.
5. Файл-хранилище: «Обновить» чужой занятый вид → Warn в логе, прогон не откатывается.
6. 3D после обновления заперт, ориентация сохранена.
7. Новая категория элементов (например, окно в сборке из стен) → параметр привязан и записан, элемент в спеке и на видах.
8. «Заменить» активного (открытого) вида → блокировка с сообщением; «Обновить» активного вида — работает.
9. Сборка Debug.R21/R25 без ошибок.
