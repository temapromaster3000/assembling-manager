# Telegram-бот Assembling Manager

Управление сортаментами труб Revit из Telegram: запрос → предпросмотр → подтверждение
кнопкой → применение. Бот работает на этом же компьютере, где открыт Revit.

## Как это устроено

```text
Telegram (long polling, без входящих портов)
   │
   ▼
@grinev/opencode-telegram-bot (Node.js)
   │  локальный HTTP API, только 127.0.0.1
   ▼
Отдельный OpenCode-сервер песочницы
   │  свой конфиг, своя БД, свой набор агентов
   ▼
MCP-сервер Assembling Manager (stdio)
   │  именованный канал + токен
   ▼
MCP-мост внутри Revit
   │  ExternalEvent → TransactionGroup
   ▼
Revit API
```

Почему отдельный OpenCode-сервер:

- бот не видит остальные проекты и сессии обычного opencode;
- в песочнице один агент `revit`, которому разрешены только MCP-инструменты
  `revit_*`; файлы, shell, веб и субагенты запрещены;
- основной opencode и его настройки не меняются;
- `/opencode_stop` в боте останавливает только сервер песочницы, а не ваш
  основной сервис.

## Безопасность

- Только один разрешённый Telegram ID (`TELEGRAM_ALLOWED_USER_ID`), остальные
  сообщения игнорируются.
- Long polling: бот сам обращается к Telegram, входящие порты не открываются.
- OpenCode-сервер песочницы слушает только `127.0.0.1`.
- Токен бота и Telegram ID хранятся в переменных окружения пользователя, не в git.
- Агент не имеет доступа к файлам, shell и сети; только `revit_*`.
- Запись в модель включается отдельным выключателем в настройках плагина Revit.
- Перед записью агент показывает план и спрашивает подтверждение кнопками.
- `previewId` одноразовый; повторное нажатие не применит изменение дважды.

## Что нужно заранее

1. Windows 10/11, Node.js 22.14+ (проверено на Node 24), OpenCode V2.
2. Установленный плагин Assembling Manager с MCP-сервером
   (`%APPDATA%\AssemblingManager\McpServer\AssemblingManager.McpServer.exe`).
3. Бот в Telegram:
   - напишите `@BotFather` → `/newbot` → скопируйте токен;
   - узнайте свой числовой ID у `@userinfobot`.
4. В Revit: **Assembling Manager → Настройки → Включить локальный мост**.
   Для изменения сортаментов также **Разрешить изменение модели из чата**.

## Первая настройка

1. Дважды щёлкните `setup-telegram-bot.bat`.
   Скрипт:
   - при необходимости установит `@grinev/opencode-telegram-bot`;
   - создаст песочницу в `%LOCALAPPDATA%\AssemblingManager\TelegramBot`;
   - запишет конфиг OpenCode, агента `revit` и инструкции;
   - спросит токен бота и Telegram ID, если они ещё не заданы;
   - перенесёт credentials `opencode-go` из обычного opencode в песочницу;
   - создаст стартовую сессию и выберет её для бота.

2. Если токен нужно поменять позже — запустите `configure-telegram-bot.bat`.

3. Запустите `start-telegram-bot.bat` и не закрывайте окно, пока пользуетесь ботом.

4. В Telegram отправьте боту `/start`, затем, например:
   - «Покажи сортаменты труб»;
   - «Покажи размеры сегмента Сталь углеродистая»;
   - «Добавь в этот сегмент DN90, наружный 102, стенка 4».

## Как выглядит изменение

1. Бот показывает план: сегмент, операция, DN, размеры, сколько труб затронуто.
2. Под планом — кнопки **«Применить»** и **«Отмена»**.
3. После «Применить» opencode дополнительно покажет запрос разрешения
   (`revit_apply_pipe_size_change`) — это второй предохранитель. Нажмите
   **Allow once / Разрешить один раз**.
4. Бот покажет фактический результат. Один вызов — один шаг отмены в Revit (Ctrl+Z).

Если попросить только посмотреть план, бот не будет предлагать применение.

## Остановка

- `Ctrl+C` в окне `start-telegram-bot.bat` — останавливает бота и сервер песочницы.
- `stop-telegram-bot.bat` — останавливает сервер песочницы, если окно бота
  закрылось нештатно.
- `/opencode_stop` в Telegram — останавливает только сервер песочницы.
  Основной opencode не затрагивается.

Автозапуск пока не настроен — это отдельный future-план:
[`docs/future/telegram-bot-autostart-plan.md`](../../DOCS/future/telegram-bot-autostart-plan.md).

## Где лежит и что писать в логи

Песочница и логи:

```text
%LOCALAPPDATA%\AssemblingManager\TelegramBot\
├── bot\.env                  # несекретные настройки бота
├── bot\settings.json         # выбранный проект, сессия, агент, модель
├── bot\logs\                 # логи Telegram-бота
├── config\opencode\          # конфиг песочницы (агент revit, MCP)
├── data\opencode\            # БД, сессии и credentials песочницы
├── workspace\AGENTS.md       # инструкции агенту
├── logs\                     # логи OpenCode-сервера песочницы
└── server-password.txt       # пароль локального сервера песочницы
```

Лог плагина Revit (строки `[MCP]`):

```text
%APPDATA%\Autodesk\Revit\Addins\AssemblingManager\Logs\assembling-manager-*.log
```

## Частые проблемы

| Симптом | Что проверить |
|---|---|
| Бот молчит | Запущен ли `start-telegram-bot.bat`; правильный ли токен; ваш ли Telegram ID в whitelist |
| `BRIDGE_NOT_FOUND` | Revit открыт? В настройках плагина включён «Включить локальный мост»? |
| `WRITE_DISABLED` | В настройках плагина включено «Разрешить изменение модели из чата» |
| `PREVIEW_EXPIRED` | Предпросмотр старше 10 минут или уже использован — повторите запрос |
| `CATALOG_CHANGED` | Каталог изменился между предпросмотром и применением — повторите запрос |
| `WORKSHARING_BUSY` | Элементы заняты другим пользователем файл-хранилища |
| `TIMEOUT` | В Revit открыто модальное окно — закройте и повторите |
| Порт занят | Удалите `%LOCALAPPDATA%\AssemblingManager\TelegramBot\bot\.env` и повторите setup |
| Нет модели после setup | В обычном opencode выполните вход в `opencode-go`, затем повторите setup |

## Обновление

- Бот: `npm install -g @grinev/opencode-telegram-bot@latest`, затем перезапустите
  `start-telegram-bot.bat`.
- Плагин/MCP-сервер: обновите обычным `build-and-deploy.bat` или инсталлятором.
  Путь к MCP-серверу не меняется; повторный setup не нужен, если путь прежний.
- После повторного входа в `opencode-go` в обычном opencode выполните setup ещё раз,
  чтобы обновить credentials песочницы.

## Ограничения первой версии

- Один сегмент и один размер за вызов.
- Работают только сортаменты труб (MCP-инструменты `revit_*`).
- Нет доступа к файлам, shell, веб-поиску и другим проектам.
- История диалога — обычные сессии OpenCode в песочнице; отдельного архива нет.
